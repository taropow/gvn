# 画像にウィンドウを合わせる

0.66.0では書き出し欄をステータスバーへ統合し、独立行の高さ加算を廃止した。画像表示時は30論理pxのステータスバー、非表示時は0として計算する。

0.42.0へ配布反映済み。[確認記録](verification/0.42.0-fit-window-related.json)を参照。

「表示 → ウィンドウを画像に合わせる」は画像の画素を変更せず、原寸の画像と表示中のバー・ウィンドウ枠を収めるサイズへ調整する。ツールバーより小さくしない設定がONならボタン1列の横幅を確保し、OFFならそれより狭い窓も使える。メニューバーの幅は別に確保する。作業領域を超えるサイズはその領域へ収め、画像は原寸のままスクロールして見る。

従来は変更前の窓のバーの高さを使っていた。窓幅を縮めてツールバーが折り返すと、新しく必要になる高さが足りず画像が欠けた。逆方向では不要な余白が残る。修正版は変更先の幅でツールバーとプレイヤーを測り、ステータスバー・枠と、必要な横スクロールバーの高さを加える。元の窓が広い場合・狭い場合で、同じ画像と設定は同じ矩形になる。

窓の中央を基準にする設定は、操作前の矩形の中央を保持する。最大化から戻す時も、操作前の中央と復元後の枠寸法をそれぞれ使う。静止画・空表示の下限はWindowsの最小追跡サイズ、アニメは下部のプレイヤーを収める下限を保つ。静止画に340×240の固定下限を適用する動作は、0.33で既に解消している。[参照と起動配置](gvn-window-customization.md)に0.45の96DPIで136×39だった観測を保持している。

「大きい画像だけデスクトップに合わせる」は、小さい画像なら原寸で窓を合わせ、大きい画像なら作業領域へ窓を合わせて画像をフィットする。幅超過・高さ超過の両方を確認した。通常と全画面の指定、フィット方法、倍率維持は従来どおり独立する。画像・Alpha・Undo・変更済み状態は表示方法の変更では変えない。

修正前の本体では新規1件が失敗し、画像領域の不足を再現した。修正後は本体4件と専用81の49操作・2画面が成功した。幅900と136からの窓合わせ、ツールバー下限ON/OFF、バー非表示、最大化時の中心、6方式のコマンド、通常/全画面、アニメの最小サイズを確認した。透過コピーでは隠れたRGBと半透明を含む全RGBAを照合した。2画面では136×482の折り返しと695×193の1列表示のどちらも80×96の画像とアイコンが収まり、ステータスバーが画像の下に置かれた。

既存207件の本体テストの本文・判定は維持した。最初の修正で検出された最大化時の中心の差分と、追加試験の変数名のWindowsマクロ衝突も修正し、失敗記録を残している。全体209件・CTest・既存自動操縦全体・性能測定は繰り返していない。物理モニターの全DPIやMassiGraとの全装飾の画素完全一致を確認した意味ではない。

実装: [表示方針](../src/viewer.cpp)、[バーの実寸計測](../src/ui.cpp)。参照: [表示オプション](http://www.massigra.net/massigrahelp/currentver/m_v_disp.htm)、[ウィンドウ設定](http://www.massigra.net/massigrahelp/currentver/d_prop_wnd.htm)。設定の残項目、実プリンタとクリスタ受信などは全体GOALで継続する。

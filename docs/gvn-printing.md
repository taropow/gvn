# 印刷

## 0.54.0: 印刷濃度が強く効く不具合を修正

[確認記録](verification/0.54.0-print-density-related.json)。参照版の実PDF12出力で全11段階を確認したところ、GVNの濃度変換はグレーで最大45の差があり、薄く/濃くする効果が強すぎた。逆ガンマを千分の一単位に丸める参照出力の挙動へ合わせた。

新規回帰1件は修正前に失敗し、同じデータと本文で修正後に成功した。以前の印刷6件と影響するAppPrint1件も通り、実C++の変換表を参照PDFと同じJPEG条件へ通す独立照合では3,072色見本の差が0だった。元の224件のApp本文を維持し、全体・起動性能・合格済みGVNドライバの検査は繰り返していない。

印刷は実機未確認の判定を維持する。物理用紙・機種ごとの色や余白、実クリスタ受信等は別の残件で、全体GOALは未完了。通常/軽量0.54.0へ反映し、配布本体の主要10経路も通過した。以下は以前の記録。

## 0.45の実ドライバ確認

0.45へ配布反映済み。Microsoft Print to PDFの実ドライバで本体と同じスプール処理を検査した。[確認記録](verification/0.45.0-print-driver-related.json)を参照。

2ジョブ・3ページを出力し、2部指定、現在コマ、白への透過合成、時計回り回転、中央/右下の配置と濃度を独立したPDFium描画で照合した。A4/600dpi、30点のRGB差は最大1。開始済みの別ジョブは実際の取消ボタンでAbortDocし、ジョブが消滅してPDFを残さないことを確認した。取消は最初のページ開始前であり、全タイミングを検査した意味ではない。元のRGBAとWindowsの既定プリンタは変わらなかった。

実際の本体print_imageから設定画面とWindowsのPrintDlgWも起動し、プリンタ設定の取消・PDFの選択・本体画面の取消を確認した。この設定試験ではジョブを送らず、合格済みのPDF出力も繰り返していない。PDF出力試験はDOCINFOの出力ファイル名を指定し、ドライバの保存先画面を省いた。通常の本体は出力名未指定の従来動作を保持する。

紙への出力、機種固有の色/余白、MassiGraの濃度式との画素一致は別の未確認として残す。実ドライバの確認を全機種保証や全体GOALの完成とは扱わない。以下は従来の設定仕様と過去の確認範囲。

0.40.0へ配布反映済み。[関連確認](verification/0.40.0-print-related.json)を保存した。0.40時点の単体/UI6件、本体3件、専用54操作2画面が成功。実プリンタの確認範囲とは区別する。

「ファイル → 印刷」で専用画面を開く。表示中の画像と選択中のコマ、DPIだけを変更した場合の有効な解像度を使う。画像、選択範囲、画素編集、Undoを変更しない。

## プリンタと用紙

プリンタ名、用紙の向きと実寸、部数を表示する。「プリンタの設定」でWindowsのプリンタ設定画面を開く。DEVMODE/DEVNAMESはアプリ側のコピーを使う。Windowsの既定プリンタや永続設定を書き換えない。同じプロセスでは選んだプリンタ設定を保持し、次回起動時はWindowsの設定から始める。プリンタの取得やドライバの読み込みは印刷を開いた時に行う。

プリンタが取得できない時も設定画面を開けるが、印刷ボタンは無効にする。プリンタの選択を取り消すと、直前のプリンタを保持する。部数は1〜9999。複数部は出力前に確認する。

## 余白と位置

上下左右の余白を個別に指定する。単位はcm/inch。プリンタが報告する最小余白より小さい値は、実際の配置では最小余白まで引き上げる。最小余白も画面に表示する。余白で用紙を使い切る指定はエラーにし、印刷できない。

位置は左上・上・右上・左・中央・右・左下・下・右下の9種類。マウスのほか、Tabで移動してSpaceで選択できる。はみ出す画像にも同じ配置規則を適用する。

## 画像のサイズ

| 指定 | 挙動 |
| --- | --- |
| 印刷領域に収める | 縦横比を保ち、領域内へ収める |
| 印刷領域を埋める | 縦横比を保ち、領域を覆うまで拡大し、はみ出しを切り取る |
| 印刷領域に引き伸ばす | 領域の幅・高さに個別に合わせる |
| 画像のDPI値に従う | 水平・垂直DPIから実寸を計算する。両方不明なら72DPI、片方だけ有効ならその値を共用する |
| 指定サイズ | 幅・高さを直接指定する。最大100000cm。印刷領域を超えた部分は切り取る |

「元の縦横比を保つ」は、指定サイズで幅または高さを入力した時にもう片方を調整する。長さの単位を切り替えても、物理的な寸法を保持する。

## プレビュー、濃度、回転

プレビューは用紙・余白内の領域・配置した画像を表示する。原画像のサイズで複製せず、プレビューの表示寸法だけに縮小して描く。画像の余白外と、用紙外の部分を切り取る。

濃度は-5〜+5。0は変更せず、負で薄く、正で濃くする。白・黒・原色の端点を保持するガンマ変換を使う。0.54の実測に合わせ、逆ガンマの千分率は-5〜+5の順に1250/1200/1150/1100/1050/1000/952/909/870/833/800とし、指数には1000をこの値で割った値を使う。透明部分は白へ合成する。画面表示やコピーする元RGBAは変更しない。0.54では全11段階の3,072色見本を実出力で照合した。JPEG圧縮前の値とPDF色値を直接比べると標準でも最大4の差があるため、参照のJPEG条件を再現した上で実C++の変換表を比較し、差0を確認した。

自動回転は「しない」「左へ90度」「右へ90度」。画像と余白内の印刷領域の縦横が異なる場合にだけ回転する。DPIで実寸を指定している場合は、回転とともに水平・垂直DPIの軸も交換する。

## 出力と確認範囲

出力はGDIを使う。画像の配置、余白による切り取り、白へのAlpha合成、濃度、回転を反映する。部数はアプリ側のページ数で管理し、プリンタドライバ側の部数を1にして二重に増えるのを防ぐ。印刷中はキャンセル画面を表示し、スプールの中止を要求できる。

専用試験では非表示の所有デスクトップ、合成画像、仮想プリンタ情報、GDIのメモリ用紙を使う。ユーザーのプリンタへ紙を出す試験や既定プリンタの変更は行わない。ドライバの設定画面・スプール・部数・中止は上記0.45で実PDFドライバを確認した。物理的な紙の色や余白は引き続き別の確認範囲とする。

参照: [MassiGra印刷画面](http://www.massigra.net/massigrahelp/currentver/d_print.htm)、[Microsoft PRINTDLGW](https://learn.microsoft.com/en-us/windows/win32/api/commdlg/ns-commdlg-printdlgw)、[AbortDoc](https://learn.microsoft.com/windows/win32/api/wingdi/nf-wingdi-abortdoc)。実装は[配置と描画](../src/printing.cpp)、[専用画面](../src/print_dialog.cpp)、[プリンタと出力](../src/print_output.cpp)。

画面レビューで、初回の選択欄が捕捉画像に描かれない問題を検出し、既存の設定・リサイズと同じ描画方法へ揃えた。単位の往復で「1」が「0.999999999」になる表示も修正した。表示文字列が変わっていない項目は内部の物理寸法をそのまま保持する。

# 画像用スクロールバーの実装契約（0.6.0）

MassiGraの[ウィンドウ表示メニュー](http://www.massigra.net/massigrahelp/currentver/m_v_wnd.htm#scrb)に合わせ、通常表示と全画面の有効状態を別々に保存する。設定 → バーにも2つのチェック欄を追加する。既定は両方無効とし、既存INIにキーがなくても従来の表示を保つ。

有効でも画像が表示領域内に収まる軸は隠す。右側に縦、画像の下に横の実SCROLLBAR子コントロールを置く。アニメーションでは、画像・横スクロールバー・下部プレイヤー・ステータスの順にする。画像座標の原点は上部ツールバーの直下とし、スクロールバーを画像領域や選択座標へ含めない。

片方のバーで表示領域が減ると、もう片方も必要になる場合がある。最大3回の配置計算で両軸を決める。自動フィットでは最終表示領域で倍率を計算し、手動ズームでは倍率を保つ。移動量を画像の端で制限し、原寸・ズーム・フィット・画像切替・サイズ変更・通常/全画面切替で表示状態とつまみを同期する。

矢印は16 DIP、ページは表示領域から16 DIPを引いた量、Home/Endは先頭/末尾へ移動する。修飾なしの方向・ページ・Home/Endキーは、フォーカスを持つ実スクロールバーへ渡す。その他のキーは通常のアプリコマンドへ渡す。マウスによる画像移動もつまみへ反映する。

範囲・表示量・現在位置はSCROLLINFOの32bit値を使う。つまみの通知では[GetScrollInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getscrollinfo)の`nTrackPos`を読み、WM_HSCROLL/WM_VSCROLLの上位16bitを位置として使わない。アニメーションのシークバーは送信元HWNDで区別し、従来の停止・フレーム移動を保つ。

画像モデルと保存・コピー・OLEの画素は変更しない。静止画と停止中のアニメで、スクロール後のPNGクリップボード往復と元RGBAの一致を確認する。

検証は`canvas_scrollbars_resolve_fit_and_coupled_axes`、`native_canvas_scrollbars_ranges_keyboard_and_fullscreen`、`12-canvas-scrollbars.gvn`。専用自動操縦は実コントロールのキーと本体のキー配送を通し、透明画像、全画面、狭いアニメプレイヤー、設定保存とリセットを確認する。2000×1の画像を5000%へ拡大する統合試験では、65,535を超える位置へEnd/PageUp/Homeで移動する。

物理マウスでのつまみドラッグ、実モニタをまたぐDPI変更、外部ソフトへのOLE配送はこの試験の範囲外。ファイル名の重ね表示は別の未実装項目として継続する。

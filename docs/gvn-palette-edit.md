# パレットの番号ごとの編集

0.49.0。色番号単位の基盤に、編集画面・メニュー・実Appのプレビュー/適用/取消/Undoを接続した。機能084は実装済み、S079は部分対応を維持する。[画面とアプリの確認記録](verification/0.49.0-palette-ui-related.json)と[基盤と参照の記録](verification/0.49.0-palette-edit-foundation.json)を参照。通常/軽量の0.49.0へ反映した。

## 基盤

`edit_palette`は、元パレットと番号が現在RGBAに一致する静止1コマを受け取り、指定された色表を適用する。同じRGBの項目が複数あっても番号を統合しない。未使用の色表項目も編集でき、ビット詰め番号、行末の未使用ビット、各項目のAlphaを保持する。透明項目の隠れたRGBと半透明も維持する。

元のPNG形式・パス・読み込み情報・画像メタデータを保ち、RGBAの出力領域を1回確保する。入力は不変で、確保失敗時も元画素・色表を変更しない。色表サイズの変更、Alphaの変更、複数コマ、現在画素に合わない番号情報、不正な形状を拒否する。PNG保存を再デコードして、元番号と編集後の全RGBAが一致することを確認した。これは基盤の確認であり、実AppのUndoや画面操作の完了を示さない。

## MassiGraでの実測

公式0.45の独立した所有プロセスと、生成した4ビットPNGを使用した。色番号0と1が同じRGBの素材で番号1だけをRGB(11,22,33)へ変え、「適用」後に「キャンセル」すると、番号1の画素だけが変化した。元番号0と全ビット詰め番号を保持し、その後の未適用変更をキャンセルしても先の確定分は残った。コピーした4BPP BMPの全番号・色表・画素も独立照合した。

初期番号は0、プレビューは初期ON、変更前と適用後の「適用」は無効だった。番号7の入力でその色のRGBを表示し、プレビューOFFをOKで確定すると、正常終了・再起動後もOFFになった。番号は再起動後0へ戻った。アニメ表示を開始した実ウィンドウではパレット編集とコピーのメニューが無効だった。GVNのAlpha対応やアニメの現在コマコピーは、従来のユーザー要望を維持する。

## 実装した画面と動作

| 項目 | 必要な動作 |
| --- | --- |
| メニュー | 画像に「パレット編集」を追加する。既存コマンド番号と「色を置き換える」を保つ。パレットを持つ静止画で有効にする |
| 番号と色表 | 数値入力と色表のクリックで選択し、選択番号を赤枠で表示する。重複色と未使用項目も個別に扱う |
| RGB | 0〜255の数値、3本のスライダー、標準色選択を連動させる。Alphaは変更しない |
| 表示 | 選択色と、マウスが指す番号/RGBの情報を別々に表示する。透明色は市松上に表示する |
| プレビュー | 編集中だけ表示へ反映する。元画像とUndoを変更せず、短時間の連続入力をまとめる。選択肢を保存し、再起動時に復元する |
| 適用 | 画面を閉じず、変更した色表を確定する。確定した色表を次の基準とし、変更が無ければ無効にする |
| OK / 取消 | OKで未確定分を確定して閉じる。取消は未確定プレビューだけを戻し、既に適用した変更を残す |
| 画像の変更・失敗 | 読み込み完了等で対象が変わった場合は古い候補を適用しない。確保・設定保存に失敗した場合も現在画素とUndoを保つ |
| 検証 | 実画面の入力・色表選択・適用・取消・プレビュー保存を確認し、PNG/BMPの保存、Alpha付きコピー、実AppのUndoを照合する |

番号・RGB・色選択・赤い選択枠・指している色の情報・適用/取消の規則は[公式ヘルプ](http://www.massigra.net/massigrahelp/currentver/d_palette.htm)にも対応する。アニメ合成GIFの元番号保持と色深度切り替えは別の残項目として維持し、今回の基盤だけで完了にしない。

## 確認範囲

新規画面6件・実App4件、専用自動操縦86操作、PNG2/BMP1の全2553画素・番号・色表を照合した。BMPは白背景合成となり、Alpha保持にはPNGを使用する。全210件を再実行した結果ではない。画面のRGB情報は同じ項目にカーソルが留まったまま編集しても更新する。標準色選択のRGB入力・確定・取消は実ダイアログで確認したが、専用デスクトップのWM_PRINT画像に出ない標準ダイアログのグラデーション領域は外観確認に含めない。

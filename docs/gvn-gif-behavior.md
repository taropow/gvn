# GIFの速度制限・ループ・背景処理

2026年10月19日。MassiGra 0.45の設定S029を0.23.0へ反映した。
関連段階の記録と、最新の全体回帰・配布検査を分けて保存する。全体GOALは未完了。

## 0.23.0で検証した範囲

[最初の基盤検証](verification/0.23.0-gif-foundation.json)に続き、[再生と境界の追加検証](verification/0.23.0-animation-related.json)で関連7 CTest・209個の名前付きケース、専用43の220操作・5画面が成功した。現在の関連検証は設定34、GIF24、Loader25、実App99ケースを含む。設定画面は5択・取消・適用・初期化・他タブの保留値、ファイル指定回数と無限再生の切替を検査した。初回表示3回は約77～131msだったが、あらゆるPCでの上限を保証する値ではない。

修正前に失敗した7ケースと共通ヘルパーは、同じ本体のまま成功した。GIFの遅延0を100msとして扱い、有限回数を再生へ接続し、不正disposal値4～7を各モードに従って正規化する。圧縮画像の展開は引き続きlibplumを使う。正規化が必要な場合だけ別バッファを作り、入力ファイルを書き換えない。拡張はGIFの構造に従って走査し、コメント中の偽のループ拡張や切り詰めも検査した。

再生は周回数を数え、最後のコマで停止する。終了後の再生ボタンは先頭から再開する。シークとコマ送りは周回状態をリセットする。新しい設定ファイルでは、読み込みタブの「GIF / APNGの指定回数に従う」を既定ONにする。プレイヤーでループをOFFからONへ切り替えると、この制限を解除して無限に繰り返す。OFFは現在の周回の末尾で停止する。ツールチップには「ファイル指定:N周」「無限」「オフ」を表示する。設定から指定回数を再度有効にでき、画像の再読込は不要。旧版の`animation_loop`だけがあるINIは、以前のON=無限という動作を引き継ぐ。

GIFは遅れた場合もコマを飛ばさず、1回の通知で次の1コマへ進む。制限なし・IE風・Chrome風では、遅れが次のコマの時間未満なら持ち越し、それ以上なら捨てる。Firefox風・Opera風では持ち越さない。[公式0.45の描画へ意図的な負荷を加えた60測定](verification/gif-clock-reference-0.45.json)で、この違いと全コマの描画順を照合した。OS時計は変更していない。APNGは従来の経過時間に沿う時計を維持し、大きな値は周回単位の計算と境界検索で処理する。`UINT64_MAX`も検査した。

タイマー通知間の1ms未満の端数を保持する。15.9ms刻み19回を302.1msとして扱うテストは、修正前には285msへ切り捨てられて失敗し、同じケースで修正後に成功した。このケースだけはテスト専用の時計を供給し、通常の本体は`steady_clock`を使う。専用自動操縦の有限・無限再生は実OSタイマーで確認した。

GIFモードは読み込みオプションとキャッシュ識別に含める。未編集のGIFは設定適用後に再読込する。PNG・APNGの表示中はこの設定だけで再読込しない。この静止画保持の差分も実Appで修正前に再現し、同じケースで修正を確認した。編集中の画像やUndoの内容はそのまま保持する。

60通りの参照と一致する合成画素、別のRGBA検査、下部プレイヤーからのコピーで透明・不透明の値を確認した。専用43の有限再生は実OSタイマーで進め、停止・再開・コマ送り・ループ切替とソースファイルの保持も検査した。取得した設定画面と市松表示も目視で確認した。

ループ拡張のデータを複数のサブブロックへ分けたGIF、最大値65535、重複拡張・不正GCE・キャンバス寸法、APNGの1/2/最大回数と除外ポスターも検査した。APNGの回数は[PNG仕様](https://www.w3.org/TR/png-3/#acTL-chunk)の整数上限2³¹−1まで。初回テストが2³²−1を有効と誤認した失敗記録も保持し、製品やライブラリの検査を緩めず、上限超過は拒否する。分割ループ拡張・遅れ・無限指定・静止画保持の修正前ケースは、本体を変えず成功した。

0.23.0でGIF速度制限の5択、有限回数と明示ループONの無限再生、遅延時のコマ送り、時計端数を補完した。公式90ケースと描画負荷60測定、全34項目・99統合ケース・専用43本7,365操作・169画面、配布10経路と実プロセス9+13+3ケースが成功。[最終範囲](verification/0.23.0-gif-stage.json)を保存する。保存済みクリスタ2試料の全RGBAと再コピーも成功。設定台帳は122実装済み/18部分対応/31要照合/2代替。S029を実装済みへ進め、回転順・他設定・性能・外部受信の未確認は全体GOALで続ける。

## 参照方法

[公式ヘルプの表示設定](http://www.massigra.net/massigrahelp/currentver/d_prop_view.htm)には、速度制限の選択により遅延、ループ回数の解釈、異常な背景処理が変わるとある。今回の再取得は502となったため、2026年10月17日に保存した公式本文と、ハッシュ確認済みの公式0.45を使用した。

専用の非対話ウィンドウステーションで、プローブ自身が起動した参照用子プロセスだけを操作する。一般のComputerUse、ユーザーのウィンドウ、ユーザーのクリップボードは使用しない。既定値と選択肢は実際の設定コントロールから読み取る。生成したGIFの描画は、その子プロセスに限ったGDI呼び出しの観測で確認する。OS時計や待ち時間は変更しない。ソース、観測用バイナリ、参照実行ファイル、生成GIFと取得画素のハッシュを記録する。

これは起動速度やDWMの表示遅延の比較ではない。観測用DLL・参照実行ファイルは研究キャッシュに置き、配布物へ収録しない。文書に保存する画像はすべてプローブ生成の試験素材とその出力である。

## 5種類の選択肢

実コントロール2026の順序は、制限なし、IE風、Firefox風、Opera風、Chrome風。既定値は「制限なし」。ブラウザの現在の実装を再現するという意味ではなく、MassiGra 0.45の各選択肢を対象にする。

| モード | GIF遅延値0 | GIF遅延値1（10ms） | 値2～9 | 有限ループ値Nの解釈 |
| --- | --- | --- | --- | --- |
| 制限なし | 約100ms | 短い待ち時間 | 元の時間に沿う | N+1周 |
| IE風 | 約100ms | 約100ms | 約100ms | N+1周 |
| Firefox風 | 約100ms | 約100ms | 元の時間に沿う | N周 |
| Opera風 | 約100ms | 約100ms | 元の時間に沿う | N周 |
| Chrome風 | 約100ms | 約100ms | 元の時間に沿う | N+1周 |

遅延の単位は1/100秒。上表は生成素材で得られた描画間隔の傾向を示す。特に短い間隔はOSの待ち時間粒度の影響を受け、実測値だけから正確な内部しきい値や全条件の誤差補償を証明したとはしない。Firefox風・Opera風では20～110msの各コマの待ち時間が粒度に沿って長くなる。追加の描画負荷測定では、次のコマが100ms/300msの場合、0～350msの負荷で持ち越しの条件とコマを飛ばさないことを確認した。物理画面への提示時間や長時間の全負荷条件を保証する測定ではない。

ループ拡張がない場合は全モード1周。値0は全モードで繰り返す。値1、2、3は各モードの実際の描画順で確認する。有限再生終了時には最後のコマを保持する。

## 背景処理の不正値

3コマの合成結果を全画素で取得する。全体を赤、左半分を緑、右半分を青の順に描き、緑コマのdisposal値を変える。通常の0・1は緑を残し、2は左側を背景へ戻し、3は緑を描く前の赤へ戻す。

| モード | 不正値4 | 不正値5 | 不正値6 | 不正値7 |
| --- | --- | --- | --- | --- |
| 制限なし | 残す | 残す | 残す | 残す |
| IE風 | 描画前へ戻す | 描画前へ戻す | 描画前へ戻す | 描画前へ戻す |
| Firefox風 | 描画前へ戻す | 残す | 残す | 残す |
| Opera風 | 残す | 残す | 背景へ戻す | 描画前へ戻す |
| Chrome風 | 描画前へ戻す | 背景へ戻す | 背景へ戻す | 背景へ戻す |

透明フラグを全コマ、先頭だけ、2コマ目だけに設定した場合も確認する。参照出力は表示用のRGBであり、RGBAの保持を証明する資料には使用しない。GVN側のアルファ保持、背景色選択、埋め込み背景色との関係は独立した画素検査で確認する。

## GVN側で埋める項目

[参照90ケースの集計](verification/gif-reference-0.45.json)と、[0.22.0の修正前7ケース](verification/gif-before-fix/report.json)を保存した。製品コードを変更する前に、同じ既存ライブラリで、遅延値0、ループ値1、不正disposal値4～7、有限再生終了の7件が失敗することを確認した。同じケース本体を0.23.0の`gif_behavior`へ組み込み、成功を確認した。0.22.0の全33 CTestとは別の追加回帰である。

1. 表示タブの5択、既定値、INIの保存・読み戻し・不正値、取消・適用・ページ初期化を接続する。
2. GIFの遅延値0と短い遅延をモードに従って扱う。GIF以外の静止画・APNGを巻き込まない。
3. ループ拡張なしと明示値1を区別し、ファイルの有限回数を再生に反映する。ループ切替、再生再開、シーク、コマ送りと組み合わせて検査する。
4. 不正なdisposal値を上表に従って処理する。画像展開は既存ライブラリを使い、GIFの圧縮デコーダを独自実装しない。拡張情報の走査や正規化では切り詰め・範囲外・過大入力を検査する。
5. モードをキャッシュキーに含め、設定変更後に古い合成結果を返さない。編集中の画像・Undo・クリップボード由来の画像を保持する。
6. 停止、終了コマ、遅れ、巨大な経過時間、長時間再生、APNG、透明画素、保存・コピー・OLE出力を回帰検査する。
7. 実コントロールと下部プレイヤーを専用自動操縦で検査し、全体回帰と配布版の検査後に実装済みへ進める。

## 再現

参照ZIPを既存の研究キャッシュに用意した状態で、次を順に実行する。独立した参照プローブは同時実行しない。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/reference_gif/build.ps1
python -X utf8 tools/probe_massigra_gif.py timing
python -X utf8 tools/probe_massigra_gif.py loops
python -X utf8 tools/probe_massigra_gif.py background
python -X utf8 tools/verify_gif_reference.py
```

各実行は`.cache/gif-reference/run-*`へ結果とソースを保存し、所有する参照プロセスの終了を確認する。参照ZIPや参照実行ファイルのハッシュが違う場合、観測用ソースまたはバイナリがビルド記録と違う場合は実行しない。

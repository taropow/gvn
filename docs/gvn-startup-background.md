# 起動直後の白い画面（0.76.3）

0.76.2の検証は、背景消去を送ったときの画素と、描画後の保存画像までだった。通常のデスクトップへウィンドウが現れる直前・直後を確認しておらず、実際の起動時の白化を防いだ証拠にはなっていなかった。

通常起動の0.76.2を実際の入力デスクトップで起動し、対象プロセスの画面をスクリーンDCから連続取得した。前回位置復元とユーザー指定位置の2条件とも、透明背景の市松模様になる前に白いフレームを記録した。最初の記録では各2枚、クライアント全体を保存する最終の比較ではそれぞれ1枚・3枚だった。中央400×220pxの判定で白い画素率100%だった。PrintWindow/WM_PRINTCLIENTを呼んだ結果ではなく、DWMが合成したデスクトップ上の画素である。物理モニターの走査やカメラ撮影ではない。

`ShowWindow`、または前回位置復元の `SetWindowPlacement` で先に表示状態となり、メイン画面と子コントロールの初回描画は後だった。この公開順序を変更する。最初の表示時だけDWMのcloakを使い、配置変更・表示状態変更と、軽いGDIによる背景・子コントロール描画を完了させてから解除する。Direct2Dの初期化と本描画は表示後の通常のWM_PAINTに任せ、非表示のまま描画デバイス初期化を待たない。最初の表示アニメーションだけ一時的に抑制し、終了時に元の通常状態へ戻す。固定sleep、DwmFlushによる合成待ち、タイマー、追加ワーカー、通常リサイズでの待機は導入しない。GDIの送出にはGdiFlushを使用する。最小化起動では不要な初回描画を省く。すでに表示されたウィンドウへの再呼び出しでも初回処理を行わない。

cloakは非表示中にもDWMが合成を継続するためのウィンドウ属性である。[Microsoft DWMWINDOWATTRIBUTE](https://learn.microsoft.com/en-us/windows/win32/api/dwmapi/ne-dwmapi-dwmwindowattribute)を確認した。DWMが属性を利用できない環境では従来の表示処理を継続する。例外時にもガードを解除して、ウィンドウが隠れたままにならないようにする。

`tools/probe_startup_presentation.py` は自分で起動したGVNだけを対象に、個別INIと検証用背景ウィンドウを使用する。通常起動のフォーカス移動は発生するが、ComputerUse、マウスやキーボードの注入、ユーザーの設定・画像・クリップボードの書き換えは行わない。画面取得時には所有するウィンドウが領域にあることを検査し、終了後に検証用プロセスと背景を閉じる。クライアント全体を保存し、白化の判定はコントロールを避けたキャンバス中央で行う。

修正後の実デスクトップ記録は6起動とも白いフレーム0枚で、最初に記録された表示から市松模様だった。前回位置復元・ユーザー指定位置について各2回、最前面設定OFFの通常ウィンドウでも各1回確認した。UI 8件・関連アプリ6件、専用自動操縦2本46操作・5画面、配布EXE主要10経路も通過した。

## 0.76.2 の対処と限界

メイン画面の `WM_ERASEBKGND` は背景を描かずに処理済みを返していた。初回のDirect2D描画に入る前は有効な描画面がなく、背景が露出する余地があった。修正前に、背景消去の通知を送っても検査用のマゼンタが残ることをネイティブ画素テストで再現した。

初回描画が成功するまでの背景消去で、現在の背景設定と同じ市松模様をGDIで塗る。市松のサイズ・2色・開始位置、および単色設定を維持し、DCのクリップを尊重する。最初の描画後は従来どおり描画済みの内容を保持する。リサイズ時に毎回背景を塗り直す処理、タイマー、ワーカー、画像バッファは追加しない。パターンの一時メモリとGDIブラシはその呼び出し内で解放する。

専用の非対話デスクトップと隔離されたクリップボードで確認する。ComputerUseやユーザーの画像・設定・クリップボードは使わない。画素テストとネイティブ描画を検証するものであり、実際のモニターでのDWM合成タイミングやちらつき頻度は測定していない。

修正後の実デスクトップ記録は6起動とも白いフレーム0枚で、最初に記録された表示から市松模様だった。前回位置復元・ユーザー指定位置について各2回、最前面設定OFFの通常ウィンドウでも各1回確認した。UI 8件・関連アプリ6件、専用自動操縦2本46操作・5画面、配布EXE主要10経路も通過した。

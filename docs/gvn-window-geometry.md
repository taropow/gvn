# 小さいウィンドウとキャプション非表示の操作

0.8.0で基盤を追加し、0.33で静止画・空表示の下限をWindowsの最小追跡サイズへ補正した。0.42では[画像への窓合わせ](gvn-fit-window.md)で変更先の幅を使うように補完した。設定の名前や保存だけでなく、実バーの矩形、画像領域、入力の配送を照合する。

## ウィンドウの最小寸法

以前はDPI換算の340×240を固定下限にしていた。大ボタンの上部ツールバー、3段のアニメプレイヤー、ステータス、画像スクロールバーを組み合わせると、バー同士が重なって画像やアイコンを隠した。専用自動操縦14で失敗画面を保存してから修正した。

現在は上部バーの実コントロールへTB_SETROWSを送り、指定幅に収まる段数と高さを得る。下部プレイヤーは通常/2段/3段の同じ配置規則で必要高さを測る。通常ウィンドウの下限は次を満たすようにする。

- 静止画・空表示ではWindowsの最小追跡サイズを使う。アニメの基本の下限340×240はDPI換算し、下部プレイヤーを収める。
- アニメでは下部の全アイコンを収める幅を確保する。
- 上部バー、下部プレイヤー、ステータス、画像の高さ64DIP、必要な横スクロールバー、非クライアント領域の高さを加算する。
- 自動表示のバーも、表示された場合の高さを予約する。
- メニューが複数段に折り返す場合は実際の非クライアント高さで補正する。
- 下限自体は現在モニタの作業領域を超えないようにする。

WM_GETMINMAXINFOの追跡下限に加え、WM_WINDOWPOSCHANGINGでプログラムによるサイズ変更にも適用する。画像を開く、バーや枠を変える、全画面から戻る場合も再評価する。全画面、最大化、最小化中には通常ウィンドウ用の拡大補正をかけない。全画面の寸法はモニタ/作業領域の設定から決める。

「画像に窓を合わせる」では最小寸法を計算してから中心座標を求める。「ツールバー幅以上にする」がOFFでも、折り返しと必要高さを扱う。

Win32の契約はMicrosoftの[WM_WINDOWPOSCHANGING](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-windowposchanging)、[WM_GETMINMAXINFO](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-getminmaxinfo)を参照。前者の既定処理は再度WM_GETMINMAXINFOを送るため、提案幅で下限を処理した場合は0を返す。

## Ctrl＋左ドラッグ

通常表示でキャプションが非表示の場合、既定のCtrl＋左ボタンをシステム標準のウィンドウ移動へ渡す。画像がない場合も利用できる。クライアント座標を画面座標へ変換し、捕捉/押下状態を解除してから、WM_NCLBUTTONDOWNのHTCAPTIONを送る。

この既定動作には次の優先順位を設ける。

- Ctrl＋左ドラッグに明示的に割り当てた機能を優先する。「何もしない」「画像をスクロール」も明示指定として扱う。
- 修飾なしの左ドラッグを別機能へ変更した場合は、その継承を維持する。
- 選択モードとF6で準備したファイルドラッグを優先する。Escで準備を解除できる。
- 他のマウスボタンとの併用、Ctrl＋Shift/Alt、キャプション表示中、全画面ではこの追加の既定動作を適用しない。

通常の「左ドラッグにシステム標準の窓移動を割り当てる」機能は継続する。設定ファイルの既存の明示割り当ては書き換えない。

参照はMassiGraの[キャプション](http://www.massigra.net/massigrahelp/currentver/m_v_wnd.htm#capb)。

## 試験と未確認の境界

`minimum_window_large_bars_animation_and_visibility`は340/360/420/560/900の幅、枠/キャプション/メニュー、APNG/GIF、途中からアニメを開く動作、全画面の実矩形を照合する。専用シナリオ14は実設定欄とネイティブコントロールを操作し、バーと画像の境界、アイコンの切れ、再生操作同士の重なり、RGBAコピーを検査する。

`captionless_control_drag_respects_customization_and_cleans_capture`と専用シナリオ15は、既定入力と明示割り当ての優先順位、全画面と選択/ドラッグ準備、捕捉の解除を照合する。自アプリのWM_NCLBUTTONDOWNを試験用サブクラスで捕捉し、HTCAPTIONと画面座標を数える。結果JSONの`system_window_move_requests_intercepted`に記録する。これはOSの移動ループの境界試験であり、物理マウスによる実移動やスナップ、別モニタでのDPI遷移まで完了した証拠にはしない。

ComputerUse/Sky、他プロセスのHWND、グローバル入力は使用しない。実モニタ間のDPI変更、特殊に狭い作業領域での全バーの同時表示、OS移動ループの実機確認は継続する。

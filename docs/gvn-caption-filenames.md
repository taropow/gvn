0.43.0へ配布反映済み。[確認記録](verification/0.43.0-caption-paths-related.json)を参照。

「親フォルダ名とファイル名」は、ドライブやUNC共有の直下ではフルパスを表示する。通常の下位フォルダでは従来どおり先頭の区切りと親フォルダ名を付ける。

| 入力の例 | 親フォルダ方式の表示 |
| --- | --- |
| G:\Pictures\子\a.png | \子\a.png |
| G:\a.png | G:\a.png |
| \\server\share\子\a.png | \子\a.png |
| \\server\share\a.png | \\server\share\a.png |

公式0.45を所有する非表示デスクトップで起動し、通常フォルダ・ドライブ直下・既存localhost共有の下位・共有直下の4経路から、実設定を変えて計12文字列を取得した。ドライブ/共有直下は、フォルダ方式でもフルパスだった。修正前のGVNはそれぞれ`\a.png`、`\share\a.png`となり、同じ記録を使う本体テストでも差分を再現した。

修正版は[PathCchSkipRoot](https://learn.microsoft.com/en-us/windows/win32/api/pathcch/nf-pathcch-pathcchskiproot)でルート後の部分を判定する。文字列だけの処理で、タイトルのためのファイル/ネットワーク問い合わせは追加しない。通常GVNの実4プロセスで合成PNGを読み、参照に対応するタイトルと、透明画素のRGBも含むコピーPNGの全RGBAが一致した。参照用・GVN用に一意名で作成したGドライブ直下の一時画像は、各実行後にハッシュを照合して削除した。共有の作成・変更は行っていない。

0.35.0へ配布反映済み。現在の検査範囲は[配布記録](verification/0.35.0-daily-use.json)を参照。

「設定」→「バー」のファイル名表示を変更する。通常画像の「親フォルダ名とファイル名」は、参照アプリの「フォルダ名以降」と同じ先頭の区切りを付ける。例えば `C:\Pictures\folder\image.png` は `\folder\image.png` になる。フルパス、ファイル名だけ、拡張子なし、名前なしの5選択肢を維持する。

ZIP内画像でもフルパスと親フォルダの設定を適用する。従来は画像自体に通常ファイルのpathがないため、どちらも `images.zip / new.png` へ戻っていた。フルパスでは `C:\Pictures\images.zip / new.png`、親フォルダでは `\Pictures\images.zip / new.png` を表示する。ZIP対応はGVNの拡張であり、MassiGraのZIP表示と同じだとする確認ではない。

読み込み待ちには現在表示している文書の場所を使う。貼り付け画像へ切り替えると文書名へ戻り、Undoで元の場所を復元する。タイトルを表示するためにファイル一覧を複製しない。全画面の重ね表示も同じタイトルを使い、画像のAlpha・コピー内容へ文字を加えない。

# アニメGIFの現在コマと元の色番号

0.53.0。対象は、GIFを合成して表示している現在コマをコピー・保存・静止画として加工する経路。PNG/APNG、PSDなどの通常RGBA表示・再生の方式は変えない。[確認記録](verification/0.53.0-gif-indices-related.json)。新規基盤8件と実App1件、独立したPNG/BMP/GIFの12出力が成功した。影響する既存94件も確認し、以前のApp223件の本文は維持した。通常/軽量0.53.0へ反映し、[配布本体の主要10経路](verification/0.53.0-daily-use.json)も成功した。

## 保持する情報

GIFの各画素が持つ元の色番号を、コマの矩形・透明番号・破棄方式と一緒に読み取る。同じRGBでも番号0と1は別に扱い、未使用の色表項目も保持する。描画済みRGBAの色から元番号を推測しない。各コマの読み取りには既存のWindows WICを使用する。[GIF形式とWICの公式説明](https://learn.microsoft.com/en-us/windows/win32/wic/gif-format-overview)。

透明な後続コマは下の番号を残し、不透明な画素はそのコマの番号へ置き換える。「背景へ戻す」は対象矩形を消し、「直前へ戻す」は描く前の番号とRGBAを復元する。元画像を描いていない余白には元番号が存在しないため、表示背景に合う色表項目を使い、必要なら空き項目へ追加する。

コマごとに異なる色表を持つGIFでは、合成後の同じ番号が複数のRGBAを表すことがある。そのコマは元番号を一枚の色表で表せないため、番号保持を使わず現在のRGBAで出力する。色表に背景用の空きが無い場合や、再構成結果が表示中のRGBAと一致しない場合も同様に処理する。

## 読み込みとメモリ

表示用の全コマRGBAに、全コマ分の番号バッファを常時追加しない。元GIFのバイト列を一つだけ不変データとして保持し、画像を共有する時もこのデータを共有する。保持量は`Image::bytes()`へ含め、読み込み予算の残りへ収まる場合だけ追加する。予算不足・確保失敗でも、既に読み込めたRGBAは利用できる。

コピー・保存・静止コマ抽出の時に、必要なコマまでを再合成する。作業用に現在キャンバス、必要な場合の直前キャンバス、読み取り中の一コマを使う。番号取得時の一時メモリと処理時間は発生する。全コマ分の追加番号バッファを保持せず、再生タイマーからこの処理を呼ばない。表示用回転は取得結果にも反映する。

## アプリでの利用

`image_indices()`は静止画像の保持済み番号を優先し、必要な場合だけ遅延データを取得する。現在の幅・高さ・全RGBAと一致する結果だけを返す。取得例外と古いデータは通常のRGBA出力へ戻す。PNG・BMP・GIFの一回の保存で同じ遅延データを重複取得しない。

- PNG保存とPNGを含むクリップボードコピーは、表現可能な現在コマの番号・色表・Alphaを保持する。
- BMPの自動色深度は、利用できる元番号に合わせて8 BPP等を選ぶ。BMPの透明部分は従来の背景色合成に従う。
- GIF静止保存は元番号を使い、透明番号・背景色・インターレース等の保存設定に従う。
- 切り抜き等で現在コマを静止画像にする時は、その一コマだけに番号を実体化し、元GIFの遅延データを切り離す。
- コピーや別名保存で元アニメを変更しない。加工後のUndoでは、元のアニメ・選択コマ・再生状態を復元する。

アニメ全体のGIF/APNG再エンコードは今回の対象に含めない。元ファイルへの現在コマの上書きを拒否する既存の扱いも維持する。クリスタの実受信・物理OLE入力等の未確認事項は別に残る。

[確認記録](verification/0.52.0-slideshow-boundary-related.json)。所有する専用ツリーを未使用のDOSドライブ文字へ割り当て、参照版と通常GVNの両方で限定OFF・次フォルダONを実行した。ループOFF/ONとも、a→z→z保持・停止で一致した。割り当ては処理後に同じ対象であることを照合して解除する。

修正前GVNはaで停止した。WindowsがDOS別名の`Z:\a`に対し、通常フォルダの`Z:\a\`をボリューム位置として返すためだった。ドライブ/共有のルートと同じ場合は採用し、深い位置は[GetVolumeNameForVolumeMountPoint](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumenameforvolumemountpointw)で実際のボリュームのマウントと確認できた場合だけ境界にする。[GetVolumePathName](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-getvolumepathnamew)の問い合わせに失敗した場合もドライブ/共有のルートへ戻す。明示された探索範囲は変えない。

追加1件は修正前に失敗、同じ本文のまま修正後に成功し、既存のフォルダ13件も通った。前進・後退・末尾・ループ・親・明示範囲と、ワーカーへ渡すファイル一覧を含む。以前のApp223件は再実行していない。

## 設定と独立性

公式ヘルプの「自動スライド」と実コントロールを基準にする。既定は全画面ON、ループON、次のフォルダOFF、開始フォルダ以下への限定OFF、ランダムOFF、間隔5秒。開始フォルダ以下への限定欄は次のフォルダがONのときに操作できる。

スライドのループとフォルダ移動は、通常の前後画像移動の末尾設定から独立させる。ランダムは次の画像を毎回無作為に選ぶ処理ではなく、ファイルリストの並び順を一時的に変更する。停止時は開始前の並び順へ戻す。開始前からランダム順なら、その指定を保持する。

## 本体で確認した10条件

同じフォルダの画像を`0,1,2,3`、開始フォルダと子孫を`root → a → a/c → b`とする。いずれも専用に作成したPNGのみを使った。

| 条件 | 観測した動作 |
| --- | --- |
| 同一フォルダ、ループOFF | 0→1→2→3と表示し、次の通知で3を保持して停止。3を表示した時点では継続中。 |
| 同一フォルダ、ループON | 0→1→2→3→0と続く。 |
| 最後の画像から開始、ループOFF | 開始時には継続中で、最初の通知で同じ画像を保持して停止。 |
| 一時ランダム、ループON | 実際の並び順のチェックが名前順からランダム順へ変化。4画像の完全な巡回を4回観測し、各巡回で4画像を一度ずつ表示、巡回順も変化。停止後は名前順。 |
| 一時ランダム、ループOFF | 4画像を巡回し、末尾の次の通知で停止。並び順は名前順へ復元。 |
| 開始前がランダム順、ループON | 巡回ごとに並べ替え、停止後もランダム順の指定を保持。 |
| 子孫に限定、ループOFF | root-0→a-0→a-1→c-0→b-0と進み、次の通知でb-0を保持して停止。 |
| 子孫に限定、ループON | 同じ深さ優先の順序で巡回し、b-0の次はroot-0へ戻る。 |
| aから開始して子孫に限定、ループOFF | a-0→a-1→c-0と進み、次の通知で停止。親のrootと兄弟bは含めない。 |
| aから開始して子孫に限定、ループON | a-0→a-1→c-0→a-0と続く。 |

乱数の具体的な順列は固定仕様にしない。完全な巡回、巡回ごとの並べ替え、停止時の並び順復元を検査する。

## GVNの設定と実装

設定画面の「スライド」タブに、全画面・ループ・次のフォルダ・開始フォルダ以下・間隔・ランダム順の6項目を置く。ループとフォルダ移動は「移動」タブの末尾処理・確認音・確認ダイアログから独立する。次のフォルダがOFFの間、開始フォルダ以下の欄は無効にし、チェック値を保持する。

INIは`slide_loop`、`slide_next_folder`、`slide_subtree`を個別に保存する。従来の`slide_fullscreen`、`slide_random`、`interval`を維持する。旧INIにキーがない場合は新規既定を使い、明示した値は保持する。既存のコントロールIDは変更していない。

開始時のループ・次フォルダ・範囲・一時ランダム・全画面オプションを、その実行の状態として保持する。実行途中でこれらの欄を変更すると次の開始から適用する。間隔の変更は実行中にも適用する。

ランダムを指定すると実リストと並び順の指定を一時的にランダムへ変える。最初の巡回では表示中の画像を先頭に保ち、ループ時は全リストを並べ替える。停止後は開始前の並び順を復元し、現在の画像に対応するリスト番号も求め直す。設定の適用・画像の保存・アプリ終了でINIを書き出すときも、一時的な並び順を永続化しない。画像や全フレームのコピーは作らない。

次フォルダの探索は既存の読み込みワーカーで行う。範囲を開始フォルダ以下に限定した場合、末尾から開始フォルダ自身の画像を確認して子孫へ深さ優先で戻る。空フォルダを飛ばし、探索の取消では途中のリストを採用しない。限定OFFでは公式ヘルプに従ってドライブ／共有の末尾で停止する。直接の公式本体との末尾照合は継続中であり、ワーカーの範囲を専用ツリーに限定した検査と区別する。

停止時はスライド由来の未完了処理を取り消し、画像・表示元・リスト番号をロールバックする。一時ランダム中の手動読み込みも、並び順の復元前に取り消す。読み込み中に開始した場合も、表示中の画像から始める。画像の失敗や変更破棄の取消では、実行表示を残さず停止する。[全画面の復元](gvn-slideshow-window.md)と併せてAlpha・アニメのコマ・選択・Undoを保持する。

自動停止時にはメニューとツールバーも更新する。実プロセスの検査で見つかった、ランダム順のチェックと「スライド実行中」のチェックが残る2経路を修正した。

## 採取方法と限界

固定ハッシュの公式0.45を、所有する非表示ウィンドウステーション・デスクトップ・設定で10プロセス実行した。元のSetTimer/KillTimerの結果を変えずに観測し、所有するメインウィンドウへ実タイマーIDのWM_TIMERを通知した。各通知の処理終了を待ち、表示ファイル、実タイマーの有無、実メニューのチェック状態を読み取った。10プロセスすべて正常終了した。

設定した間隔は600秒で、時間経過の代わりに明示的な通知を使った機能試験である。実際の待ち時間、画像読み込み時間の除外、起動速度を測定した結果ではない。参照側の観測DLLはIAT経由のAPI観測と自プロセスのウィンドウ手続き観測に使った。通常GVN.exeの検査方法とは区別する。ComputerUse、グローバル入力、ユーザーの実設定・実クリップボード・他アプリは使っていない。

開始フォルダ以下に限定しない場合のドライブ末尾とループの優先関係は未確認。ユーザーの画像フォルダへ探索が出ない追加の採取方法を用意して確認する。

[公開した採取結果と観測ソース](verification/slideshow-policy-reference-0.45.json)、[固定した移動方針の試料](../tests/fixtures/slideshow-reference/native-policies.json)を参照する。既存のGVN実装と配布版、ユーザー設定のハッシュが採取中に変わらないことも確認した。

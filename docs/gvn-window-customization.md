# 起動位置・サイズの参照仕様と実装

0.33.0で実装・配布した。公式MassiGra 0.45の38入力条件・66プロセスと、再起動後の矩形28件を基に、GVNの設定欄・保存・起動配置を補完した。全49検査・専用64本の全体回帰と設定台帳の照合も完了した。通常/軽量配布本体の検査も通過した。

## 確認した動作

| 項目 | MassiGra 0.45での観測 | 改修後のGVN |
| --- | --- | --- |
| 幅・高さ | 1、100×80、32,768、2,147,483,647を設定値として保持 | 有効な正の整数を保存・復元し、独自の340×240下限と32,768上限を外した |
| 無効なサイズ | 0、負数、空欄、文字列、範囲外の値では直前の有効値を保持 | 設定欄の直前の有効値を保持して表示も正規化する |
| 無効な位置 | 解釈できない値は直前の有効値を保持 | 同じ変換と値保持に対応。保存値の独自の±1,000,000制限も外した |
| 小さいウィンドウ | 100×80の指定は136×80、1×1の指定は136×39で起動。手動1×1指定も136×39 | 静止画・空表示ではWindowsの最小トラッキングサイズを使用 |
| 複数画面をまたぐ位置 | -1,-1や上下の画面境界をまたぐ位置を保持する | ユーザー指定の起動では仮想デスクトップ全体を基準に配置 |
| 画面の外側 | この配置でX=3,500・幅640はX=3,200へ補正 | 仮想デスクトップ内へ補正後、Windowsの配置処理を使用 |
| 中央配置 | 配置先画面の作業領域と、実際の最小サイズを考慮した中央 | 対応済み。28矩形の比較には5件の中央配置を含む |
| 設定の適用 | 位置・サイズの値を変えても現在のメイン画面の矩形は変わらない | 起動時に反映する性質を維持する |

寸法が0なら常に初期値へ戻る、という規則ではない。新規状態では480×360を保ち、620×420を適用した後では620×420を保った。位置の文字列が無効な場合も、既に適用した57,69を保持した。

寸法欄は`ES_NUMBER`付きのEdit、座標欄は通常のEditだった。文字数上限は4欄とも30,000。数値の確認にはWM_SETTEXTで入力し、実際のOK、設定画面の再表示、正常終了で書き出されたユーザー指定値を調べた。負数など、通常のキー入力では制限される文字列を与えた場合の処理も含む。

32bit符号付き整数の上端では、参照側のX＋幅の加算で保存矩形が反転する異常も観測した。入力の38条件と固定試料には、この結果も異常として明示して保持した。GVNは位置と正の寸法を維持し、中間計算を64bitで行う。実設定欄と本体で、この異常条件でも幅640を保つことを検査した。

大きい寸法値は保存と設定画面の再表示だけを確認した。巨大なサイズの参照ウィンドウとしては起動していない。

## 実ウィンドウと複数画面

画面配置を読み取ると、プライマリー3840×2160、上側、左側、下側の4画面だった。仮想デスクトップはX=-1200、Y=-1440、幅5040、高さ5200。プライマリーの作業領域の下端は2112で、位置・中央配置の捕捉中に画面配置が変わらなかったことも確認した。表示DPIは96だった。

この環境の代表例は次のとおり。

| 指定 | 再起動後の矩形 X,Y,幅,高さ |
| --- | --- |
| -1,-1、640×480 | -1,-1,640,480 |
| X=3,500、Y=0、640×480 | 3200,0,640,480 |
| X=0、Y=-481、640×480 | 0,-481,640,480 |
| X=0、Y=2,161、640×480 | 0,2161,640,480 |
| 中央、100×80 | 1852,1016,136,80 |
| 中央、左画面の640×480 | -920,131,640,480 |
| 中央、上画面の640×480 | 960,-960,640,480 |
| 中央、下画面の640×480 | 960,2720,640,480 |

自分のプロセスに作成した標準ウィンドウで、WindowsのSetWindowPos、SetWindowPlacement、仮想デスクトップ内へ補正後のSetWindowPlacementも比較した。最後の方法で、正の寸法を指定した18位置条件がすべて参照と一致した。全23条件では21件が一致し、残る2件は生の0・負の寸法を渡した条件だった。そこには設定欄の「直前の有効寸法を保持する」変換を別途組み合わせる必要がある。

この標準ウィンドウの比較はGVN本体のテストではない。画面配置を変更したり、実ユーザーのウィンドウを操作したりせず、所有する非表示ウィンドウステーションだけで確認した。物理画面での見え方、異なるDPIの画面間移動、起動速度の測定は別途の確認事項とする。

実装後は同じ28矩形を通常のGVN.exeで照合し、初回と正常終了後の再起動が全件一致した。56プロセスの入力画像と設定を個別に用意し、全プロセスが正常終了した。保存する指定サイズとWindowsが実際に適用する最小サイズも分けて確認した。

## 実装と検証

4入力欄の変換には符号付き整数のGetDlgItemIntを使い、変換できない場合は設定画面の有効値を保つ。幅・高さは正の値だけを採用する。寸法欄だけを数値専用にし、4欄の文字数上限を参照と同じ30,000にした。

有効な指定値はINIでも保持する。破損した旧INIの非正寸法については、従来の幅340・高さ240への復旧規則を維持した。これは設定画面の「有効値を保つ」処理とは別の復旧経路であり、既存のテストも保持した。

ユーザー指定の起動は寸法を持つRectから計算し、端点の加算に64bitを使う。中央配置は選択画面の作業領域を使い、それ以外は仮想デスクトップ内へ補正後、画面座標から作業領域座標へ変換してSetWindowPlacementを呼ぶ。まだ未表示なら配置中も隠したままにし、起動状態のShowWindowで表示する。前回位置を復元する方式と、追加の「Windowsに任せる」方式は維持した。

静止画・空表示の最小サイズはWindowsの値を使う。アニメでは既存の340×240を基準に、プレイヤー、カウンター、64pxのキャンバスが収まる寸法を維持する。136×39へ縮めてからアニメを開く経路と、既存の大きいバー・スクロールバーの検査も通過した。

本体189件・設定51件と関連CTest 5件が通過した。従来186件の本体テストと50件の設定テストの本文は保持し、変更前に追加3件と設定1件が失敗することを確認した。専用自動操縦10本1,453操作・44画面、通常EXE計133プロセス75条件も通過した。

新規シナリオ64は341操作で、固定した15入力条件、文字数・数値専用スタイル、適用・取消・初期化・保存、小窓とアニメ、Alphaのコピーを確認する。参照の端点オーバーフローだけは、正の寸法を保持するGVNの期待値を明示した。

最初の試行では操作333件自体は成功したが、共通の撮影後検査が正しい136×80画像を拒否した。小窓専用の撮影操作を追加し、実ウィンドウとPNGの寸法を指定値へ完全一致させて検査した。従来の撮影の幅・高さの下限と、空画像を検出する色数の確認は維持している。2枚の新規画像も確認した。

[現在の実装・関連検証とソース](verification/0.33.0-custom-window-related.json)を参照する。API値と非表示デスクトップの描画の検査であり、物理DWM、異なるDPIの画面間移動、大画像・多数起動の性能、実編集ソフト側の受信は継続する。

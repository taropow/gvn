# ビットフィールド画像の読み込み

0.56.0。[確認記録](verification/0.56.0-bitfield-loading-related.json)。設定 → ファイル読み込みの「ビットフィールド画像を読み込み時に24 BPP化（Alphaは保持）」で切り替える。参照版と同じく既定はON。

ONでは16bit BMPのRGB成分を8bitずつへ展開する。単なる保存形式の印を外すだけではなく、符号値を `round(code * 255 / max)` で展開し、参照版の色へ合わせる。画像の元ファイル・元のBPP/解像度情報は書き換えない。通常の自動BMP保存は24bitになる。OFFならRGB555/RGB565の元の符号を保持し、既存の自動16bit保存を使える。

Alphaはこの項目で削除しない。V4/V5 BMPは透明/半透明を保持し、PNG保存・コピーでもRGBAを保持する。別項目の「アルファを保持する」を明示的にOFFにした場合の背景合成は従来どおり。一般のRaw decode/クリップボード受信は表示設定を暗黙に適用せず、元データを保持する。通常ビューアは設定値をLoadingOptionsへ明示して渡す。

設定の適用で未編集のファイル・書庫内画像を再読み込みする。キャッシュキーへ独立したビットを含めるため、ON/OFF変更後に古い色深度のキャッシュを流用しない。編集中の画像とクリップボード画像は変更しない。値はINIへ保存し、旧プロファイルに項目がなければON。読み込みタブのリセットもONへ戻す。キャンセルで未適用値を保存しない。

公式0.45を隔離環境で11回正常終了させ、既定ONと、RGB555（BI_RGB/ビットフィールド）・RGB565のOFF=16bit/ON=24bitを観測した。GVNのON出力は3試料のRGBに完全一致した。基盤/実設定3件、既存設定1件、App2件、専用91シナリオ54操作を実行。独立したPillowで、OFFの16bit保存、ONの24bit保存、ON/OFF双方のAlpha付きPNGの4ファイルを確認した。設定画面の実キャプチャも確認した。

以前のApp226本文と専用86の既存アサーションを維持した。旧RGB16契約は保持モードを明示し、設定既定値の検査には新しいON値だけを追加した。無関係の全体・性能・フィルタ検査は繰り返していない。任意のBMPマスクや他形式との画素完全一致は証明していない。実クリスタ/物理操作等は引き続き未確認で、全体GOALは未完了。

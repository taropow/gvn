## 実装と検証の順序

1. 非対称の色と透明画素を持つ縦長・横長・正方形を用意し、8択の描画結果、寸法、選択の状態を固定する。元画像・参照EXE・素材・プローブ・取得画素のハッシュも保存する。
2. 高さと縦横比の異なる2枚で、漫画の左右方向、単ページ条件、前後の回転、5種類の高さ処理との組合せを確認する。条件付き回転の判定対象を実測し、推測で縮めない。
3. Exif全8方向、静止画・アニメ・ZIP・貼り付け・編集中・Undoとの順序を明記する。コピー/PNG保存/OLEの向きと、表示の市松・補間・選択座標の対応を独立に照合する。
4. 現行GVNで不足する代表ケースを先に失敗させる。参照の正解画像とテスト本体を保存し、修正後に同じケースで再検証する。
5. 8コマンド、メニューの選択表示、キー/マウス割り当て、INI保存と旧設定、読み込みとキャッシュの識別を接続する。別画像へ移っても指定を維持し、加工回転と区別する。
6. 表示ページの回転順を実装し、適用・取消・初期化・未表示ページと他ページの編集値の保持を専用自動操縦で検査する。全項目が揃ってからS039のページ全体の初期化を数え直す。
7. 既存のRGBA・元パレット・Undo・原寸の座標を維持する。表示用に大画像やアニメ全コマを毎回複製する設計を避け、必要な変換とキャッシュ容量を測定する。元ファイルのハッシュが変わらないことを確認する。
8. 関連試験、全体回帰、全専用シナリオ、配布本体と保存済みクリスタ試料を検査してから、項目単位で台帳を更新する。

## 追加参照: 透過PNG・GIFとアニメ各コマ

2026年10月20日、[形式別の参照120条件](verification/rotation-formats-reference-0.45.json)を追加した。静止画は部分アルファを含むPNG、不透明GIF、透過GIFの各24条件で、回転変更直後と再読込後のコピー結果の全RGB画素が独立した座標計算と一致した。72条件すべてで、描画元の不透明画素の向きも一致した。

参照側の透過PNGコピーは24bpp、GIFコピーは8bppだった。透過部分はRGB(128,128,128)への合成と一致し、PNGの丸め差は最大1、GIFは差0である。これをアルファ保持の証拠として扱わない。GVNはユーザー要望に従い、アルファを保持する。

アニメは不透明/透過の2形式、縦長/横長/正方形、8択の48条件で確認した。変更直後・再読込後の96組について、2コマずつ計192枚の描画元RGBが回転なしの各コマを独立に回転した結果と完全一致した。参照のコピー項目は再生中の全48条件で無効だった。GVNの現在コマのアルファ付きコピーは、追加の要件として検証する。

GIFで停止した最初のプローブは24/32bppのDIBしか扱えなかったため、元のGIF観測器を変更せず、別の観測器と1/4/8bpp対応の読取を用意した。アニメ照合側の画像サイズ取得ミス、無効なコピーの待機、画像切り替え前の旧コマも初回記録として残した。旧コマは既知の前画像と全RGBが一致し、新画像の最初の描画より前のものだけを切り替え中として記録する。正しい画像だけを抽出して失敗を隠す扱いにはしない。

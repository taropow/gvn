# ファイル読み込み設定の契約

0.10.0で読み込みタブを補完する。既定はアルファ保持。背景合成を選んだ場合だけ、読み込んだファイル画像を不透明化する。元ファイルは変更しない。

## 項目と作用

| 項目 | 既定 | 動作 |
| --- | --- | --- |
| アルファを保持 | ON | 有効な透過情報をRGBAのまま保持。OFFなら有効な透過を背景と合成 |
| 透過BMP / GIF / PNG・APNGを透過表示 | ON | OFFでは元の色を不透明にする。GIFのアニメ表示中はGIFのこの選択を無視し透過を利用 |
| GIF / PNG・APNGの背景色を利用 | OFF | 背景合成時にファイルの背景色があれば使う。アルファ保持時は適用しない |
| 透過表示の背景色 | 白 | ファイルの背景色を使わない、または背景色情報がない時の合成色 |
| アニメGIFをアニメーション表示 | ON | OFFなら先頭コマだけを読む。自動再生のON/OFFとは独立。APNGへは作用しない |
| Exif情報に従い回転 | ON | JPEGの全8方向に対応。OFFは記録画素の向き。ファイルを書き換えない |
| 隠し / システム / 隠し＋システム属性 | OFF | 3分類を独立指定。両属性を持つ画像は最後の設定だけで判定 |
| 自動再生 / ループ | ON | 従来の再生設定。GIFの先頭コマ読み込みとは区別 |

「アルファを保持」はGVNの追加項目で、ユーザーの透過クリップボード要件に合わせた既定値。MassiGraでは透過を利用する場合も読み込み時に背景と合成する。GVNでは保持をOFFにするとその背景合成を選べる。PNGの16bit・透明色情報はWICが対応する範囲で利用し、元アプリの16bit tRNSの制限は再現しない。内部はRGBAなので、ビットフィールドの24BPP変換スイッチは設けない。

読み込み設定は通常ファイル、ZIP内、見開きの両画像、先読みに同じ値を渡す。アルファ保持、各形式、背景色、Exif等の値はキャッシュの識別値にも含める。先読みと通常表示で同じ設定の画像は再利用し、設定が違う画像と混ざらない。

適用時は未編集のファイル画像だけを再読み込みする。編集中の画像やクリップボード画像を設定変更で置き換えない。これらには次のファイル読み込みから反映する。クリップボードの貼り付け自体はファイルの読み込み設定を使わず、PNG/DIBV5のアルファと隠れたRGBを保持する。市松模様は表示専用でコピーへ混ぜない。

## デコードと移行

PNGの背景はWICの`/bKGD/BackgroundColor`から取得する。RGB、グレー、パレット、低ビット深度、16bitの値を扱う。[WICのメタデータ仕様](https://learn.microsoft.com/en-us/windows/win32/api/wincodec/ne-wincodec-wicpngbkgdproperties)、[PNG仕様](https://www.w3.org/TR/png-3/#11bKGD)を参照。

GIFの通常アニメはlibplumの合成を継続する。先頭コマだけの選択ではWICで最初のフレームを読み、論理画面サイズと開始位置を反映する。後続フレームの全展開は不要。静止GIFの透過を無効にする時も、透明インデックスの元のパレット色を保持するWIC経路を使う。

旧INIに`hidden=1`だけがある時は、3属性すべてを含む従来動作を引き継ぐ。新しいINIは`hidden`、`system_files`、`protected_files`を独立保存する。読み込みタブのリセットは同タブの項目だけを戻し、他タブの編集中の値を保持する。

## 検査

生成素材は`tests/fixtures/loading`、生成方法とSHA-256は`tools/generate_loading_fixtures.py`とmanifest.jsonに保存する。V4/V5アルファBMP、PNGのRGB/パレット/2bitグレー/16bitグレー/16bit tRNS、GIFの背景色・静止/アニメ・開始位置、APNG背景、Exif8方向を含む。Exifの独立参照PNGはPillowの`ImageOps.exif_transpose`で生成する。

単体検査に加え、実Appで変更後の再読み込み、編集内容の保持、ZIP、プレイヤーの表示/非表示、クリップボードを照合する。専用自動操縦18は実設定画面と色選択、RGBA、属性の全8組、保存、ページリセットを通す。属性の変更先は試験が作ったフォルダ内だけに制限する。

これはファイル操作・移動・旧フォント等の設定まで完成したという判定ではない。全回帰後の件数とバイナリ対応は[検証記録](gvn-verification.md)へ記録する。

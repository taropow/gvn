# 色深度の変更

0.50.0。変換基盤に画面・メニュー・設定保存・実AppのUndoを接続した。機能083は実装済み、S079は部分対応を維持する。[画面とアプリの確認記録](verification/0.50.0-color-depth-ui-related.json)と[基盤と参照](verification/0.50.0-color-depth-foundation.json)を参照。通常/軽量0.50.0へ反映した。

## 参照版で確認した操作

公式MassiGra 0.45の色深度変更コマンドは40048。専用デスクトップの所有プロセスで、生成した画像だけを使用した。元が24 BPPの場合、そのラジオボタンは無効で、初期選択は「最適なBPPにする」だった。選択肢は8 BPP、16 BPP RGB555、16 BPP RGB565、24 BPP、最適化。1/4 BPPは手動の選択肢になく、2色の24 BPP画像を最適化すると1 BPPになった。

誤差拡散は初期ON。OFFで確定すると次回にも引き継ぎ、OFFへ変更してキャンセルすると保存されなかった。元が24 BPPで初期の最適化が選ばれている時、ホイール上では無効な24 BPPを飛ばしてRGB565、ホイール下で最適化に戻った。色深度画面の選択をキャンセルした画像は、コピーした色深度と全RGBが変わらなかった。

参照8経路に加え、ホイールと16 BPP誤差拡散ONを別の3経路で確認した。これはGVNの画面やUndoの確認ではない。

## 変換基盤

| 選択 | 実装した動作 |
| --- | --- |
| 8 BPP | 1/2/4ビットの既存パレットからは、重複・未使用項目と元の番号、Alphaを保って8ビットへ増色する。その他は既存のWIC量子化でRGBを256色以内に減らす |
| RGB555 | 各RGB成分を5ビットへ変換する。不透明画像には16ビット保存のための成分コードを付ける |
| RGB565 | 緑を6ビット、赤と青を5ビットへ変換する。BMP自動保存ではRGB565のビットフィールドを使う |
| 24 BPP | パレットまたは16ビットの表現情報を外す。現在のRGBA、Alpha、透明部分のRGBを変更しない |
| 最適化 | RGBAを変えずに、2色以内なら1 BPP、16色以内なら4 BPP、256色以内なら8 BPPへ整理する。色表に収まらない場合は変更しない。現在の1/16 BPPと、既に適切な色深度も変更しない |
| 誤差拡散 | 8 BPPではWICの誤差拡散、16 BPPではFloyd–Steinberg法を使う。OFFでは近い成分コードへ変換する |

入力は不変。変更不要の場合は空の結果を返すため、接続先はUndoを増やさない。複数コマ・不正な形状・不明な選択肢を拒否する。出力RGBAの確保は既存の編集用メモリ制限と失敗注入を通す。保存時に使用する元の形式・パス・サイズ・読み込み情報・DPI等のメタデータを維持する。

## Alphaの扱い

ユーザー指定に従い、全ての選択肢で元のAlphaを保持する。減色するRGBは、透明部分も含め、背景に合成する前のRGBで扱う。8 BPPの量子化入力には出力用の領域を再利用し、元画像を不透明化しない。

256項目以内のRGBA色表に収まる場合は、色番号付きの画像として保持する。同じRGBに異なるAlphaが多数ある等、RGBAの組み合わせが256項目を超える場合は、Alphaを保つためRGBAで保持する。この場合もRGBは256色以内へ減色されているが、保存は通常のRGBA PNGとなり、パレット編集の対象にはならない。Alpha付きの16ビット相当RGBもRGBAで保持し、Alphaを持たない16ビットBMPへ自動的に置き換えない。

ここでいう8/16/24ビットは選択するRGB表現であり、Alphaの追加情報を含むメモリ量を示すものではない。画面には「Alphaは維持」を明記する。BMPは半透明を保存できないため、既存の確認と背景色合成を使う。Alphaを保持して保存する場合はPNGを使う。

## 参照版との一致と差

RGB555/565の誤差拡散OFFでは、生成画像の全1122個の16ビット値が参照版のコピー結果と一致した。表示用RGBはGVNのWICデコーダーに合わせてビットを複製して展開する。Pillowによる参照BMPのRGB展開とは一部成分で1段階異なるが、16ビット値は一致し、GVNで保存・再読込しても現在RGBAを保持する。

8 BPPのパレット生成は既存のWIC、16 BPPの誤差拡散はFloyd–Steinberg法による。参照版の誤差拡散結果との全画素一致は主張しない。参照の16ビット誤差拡散結果と単純なFloyd–Steinberg法は一致しなかった。希少な量子化処理の完全な解析より、選択肢・Alpha・保存・失敗時の保持を優先する。

## 画面とアプリの動作

- 画像メニューに「減色/増色…」を追加し、既存コマンド番号とポスタライズを保つ。空の表示では無効にする。
- 上記5選択肢と誤差拡散チェックを持つ小さなタブなしの専用画面にする。全体の設定画面は従来のタブ式を維持する。
- 初期選択は毎回最適化。同じ色深度の選択肢は無効にし、ホイールでは無効項目を飛ばす。誤差拡散は初期ON、確定時だけINIへ保存する。
- OKで現在の対象へ変換し、変更した画像だけをUndoへ渡す。キャンセルでは画素・Undo・保存済み設定を変えない。
- アニメーションでは既存の確認後に表示中のコマを静止画として加工する。元アニメーションへの上書きを防ぐ。
- ダイアログ中に対象画像または表示コマが変わったら、古い結果を適用しない。確保・設定保存・変換の失敗でも元画像とUndoを保つ。
- 実画面の全選択肢・ホイール・誤差拡散・取消・INIと、実AppのAlpha付きコピー・保存・Undo・失敗時の保持を、変更箇所に絞って確認する。

基盤6件に加え、新規UI4件・実App4件、実メニューからの157操作と7出力を照合した。減色画像は全Alpha保持とRGB256色制約を、その他の出力は独立した全RGBAと番号等を検査する。画面中に対象が変わった場合や確保・設定保存の失敗では、元画像とUndoを維持する。画像情報のDPIを別途変更した状態もUndoへ戻せる。

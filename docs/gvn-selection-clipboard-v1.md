# 位置付き選択範囲クリップボード v1

2026年10月22日。自作ペイントソフトとGVNを連携させるための独自プロトコル。Windowsやクリスタの既存仕様という意味ではない。GVN 0.60.0から「選択範囲でペースト」で読み取り、選択範囲のコピー・切り取りでは標準PNG・DIBV5と同時に公開する。[操作仕様](gvn-selection-tools.md)。通常の貼り付けコマンドは従来の動作を維持する。

## 他アプリへの画像貼り付けとの両立

一度のコピーで、次の形式を同時に公開する。

1. **`GVN.Selection.v1`**: 以下のヘッダーとAlpha付きPNG。対応アプリが画像・元位置を一体で読む。
2. **`PNG`**: 通常のAlpha付きPNG。他アプリが画像として読む。`image/png`も公開してよい。
3. **`CF_DIBV5`**: 標準の32bit DIBV5。PNGを読まないアプリとのAlpha画像の受け渡し用。

独自形式へ置き換えるのではなく、標準画像に追加する。対応しないソフトでも、自分が読める標準形式から従来通り貼り付けられる。配置位置の引き継ぎは、この独自形式を理解するアプリ同士に限る。クリスタへの画像の受け渡しと、クリスタが元位置まで引き継ぐことは区別する。

## 座標・画像の定義

- 原点は**コピー元キャンバスの左上の画素境界（0,0）**。Xは右、Yは下へ増える。単位は元画像のピクセル。表示ズーム、ウィンドウ座標、DIPや実寸へ変換しない。
- コピー領域を画像に切り出した時、その画像の左上がコピー元キャンバスのどこにあったかを`origin_x / origin_y`へ記録する。
- PNGの寸法は切り出し画像の寸法。元キャンバスの寸法は別に持つ。
- 折れ線・投げ縄等の非矩形選択では、外接矩形に切り出し、選択外のAlphaを0にする。境界の半透明を保持し、選択マスクと元画像のAlphaを乗算する。市松や白背景を焼き込まない。
- レイヤーだけをコピーした場合も、レイヤーローカル座標ではなくキャンバス座標へ変換する。負の原点も表現できる。
- 元位置が分からない場合は`flags`のbit0を0にする。座標0を「元位置不明」の代わりに使わない。
- 貼り付け先のキャンバス寸法が違っても、自動的に比率を掛けて移動しない。

例: 1920×1080のキャンバスの(320,180)から、400×300の領域を切り出した場合、画像400×300、原点(320,180)、元キャンバス1920×1080とする。

## バイナリ構造

形式名はUnicode文字列 **`GVN.Selection.v1`** を`RegisterClipboardFormatW`で登録する。数値IDは実行環境で変わるので固定しない。データは`HGLOBAL`内の次の64バイトヘッダーと、それに続くPNGバイト列。多バイト整数はすべてリトルエンディアン。

| オフセット | 型 | 内容 |
| --- | --- | --- |
| 0 | 8 bytes | `47 56 4E 53 45 4C 31 00`（`GVNSEL1`＋NUL） |
| 8 | uint32 | ヘッダー長。v1は64 |
| 12 | uint32 | バージョン。1 |
| 16 | int32 | `origin_x` |
| 20 | int32 | `origin_y` |
| 24 | uint32 | コピー元キャンバスの幅 |
| 28 | uint32 | コピー元キャンバスの高さ |
| 32 | uint32 | PNG画像の幅 |
| 36 | uint32 | PNG画像の高さ |
| 40 | uint32 | `flags`: bit0=元位置が既知。その他のbitは0 |
| 44 | uint32 | 後続PNGのバイト数 |
| 48 | 16 bytes | 予約領域。すべて0 |
| 64 | PNG bytes | 標準`PNG`形式にも公開する同一バイト列 |

画像と座標を一体にして、別の画像へ誤って座標を適用しない。JSONパーサーやBase64変換は不要。HGLOBALの割当サイズには余白が生じ得るので、受信側はPNG長から有効範囲を決め、割当末尾の余白は読まない。

幅・高さは1〜65535。位置はint32で表し、画像の右端・下端計算は64bitで行う。GVNは既存の画像容量制限も適用する。未知版、未知フラグ、壊れた長さ、デコード後の寸法不一致、不正PNGは採用せず、標準画像へフォールバックして位置不明として扱う。

## コピー実装の注意

PNGを一度だけエンコードし、標準形式と独自形式へ同じバイト列を使う。必要なメモリを準備してから`OpenClipboard(owner HWND)`、`EmptyClipboard`、各形式の`SetClipboardData`、`CloseClipboard`を行う。形式ごとに`EmptyClipboard`を呼ばない。

HGLOBALは`GlobalAlloc(GMEM_MOVEABLE, ...)`で確保する。公開成功後のハンドルはOS所有となるので解放しない。失敗した未公開ハンドルだけを解放し、例外でもクリップボードのロックを解除する。クリップボード競合時の失敗も処理する。

DIBV5は124バイトの標準V5ヘッダー、32bit BGRA、RGB/Alphaマスクを使う。ヘッダー直後へRGBマスクを重ねて追加しない。画素のRGBはストレートAlpha、上下向きはヘッダーの符号と一致させる。

参照: [Windowsの複数形式](https://learn.microsoft.com/en-us/windows/win32/dataxchg/clipboard-formats)、[登録形式](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerclipboardformatw)、[メモリの所有権](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setclipboarddata)。

## 別AIへ渡す依頼文

```text
Windowsの自作ペイントソフトで、選択範囲のコピーにキャンバス内の元位置を付けたい。
添付する「gvn-selection-clipboard-v1.md」を双方の共通仕様として実装してください。

・標準PNGとCF_DIBV5を残し、他アプリへの画像貼り付けを維持する。
・同時に登録形式「GVN.Selection.v1」を公開する。上記64バイトLEヘッダー＋PNG。
・原点はコピー元キャンバス左上。コピーした画像左上のcanvas X/Yを保存する。
・元キャンバス寸法と、切り出しPNG寸法を別々に記録する。
・折れ線/投げ縄選択は外接矩形で切り出し、選択外を透明、既存Alphaと境界の半透明を保持する。
・PNGは1回だけエンコードし、標準PNGと独自形式に同じ内容を使う。
・元位置が既知ならflags=1。不明ならflags=0とし、0,0で分かっているふりをしない。
・同じソフトへの位置付き再貼り付けと、標準形式だけを読む他アプリへの貼り付けを両方確認する。
・負座標、画面ズーム、レイヤーオフセット、半透明、コピー競合/失敗を確認する。
・GVN側は別の担当がこの共通仕様の受信とフローティング貼り付けを実装する。
完了時に、形式名・ヘッダーダンプ・画像寸法・原点・Alpha一致の検証結果を報告する。
```

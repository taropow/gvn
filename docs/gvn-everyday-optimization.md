専用ブランチ `codex/everyday-optimization` で6項目を実装した。0.73.0配布版・設定・ユーザーのウィンドウを保持し、専用の非対話デスクトップと自動操縦で確認する。

- [x] 選択線・ペンの部分再描画。部分更新と全更新の画面一致、画像・Alphaを確認。
- [x] GIF/APNGの次コマ時刻に合わせるタイマーと、最小化中の表示更新抑制。再生時刻、反復、一時停止、復帰を確認。
- [x] リサイズ時の配置・状態更新の重複削減。ツールバー、ステータス、スクロール、DPIと画質復帰を確認。
- [x] コピー／OLE準備の重複削減。PNG・DIBV5・選択範囲位置・Alpha、受信側が後から読む場合も維持。
- [x] 高画質縮小の非同期化。UI受付、最新要求優先、取消・画像変更・終了時の寿命、最終画質を確認。
- [x] APNG／PSDデコードの一時メモリ削減。全画素・透明画素内RGB、合成・破棄・遅延、色深度と読み込み上限を確認。

計測は実装の影響範囲へ絞る。ファイル読み込み・CPU計算・描画・UIの応答・メモリを区別し、実測していない速度向上は断定しない。各段階の結果を残し、普段使い用 `G:\gvn\app\gvd.exe` へ反映済み。

## 実装内容

選択矩形のアニメーションは四辺の細い領域を、ペン入力は追加した線分とフチ・影の範囲を更新する。任意形状選択は境界の外接領域に限定する。Direct2Dのウィンドウ内容を保持し、初回・サイズ変更・デバイス再作成では全面を描く。選択線の実寸1pxとAlphaを維持する。

GIF/APNGは現在コマの残り時間を次のタイマー期限にする。最小化中も再生時刻を進めるが、ステータス・ツールバー・キャンバスは更新しない。復帰時に現在のコマを反映する。リサイズでは配置後のスクロールバー・ステータス再配置を省き、ステータス高さもサイズ・DPI・テーマが同じ間は再計測しない。

コピー時は元の現在コマを借用し、選択範囲がある場合だけ必要な領域を作る。DIBV5は最終クリップボード領域へ直接書き込み、位置情報付き形式も同じPNGを使う。PNGは可逆の高速圧縮を使い、通常のPNG・DIBV5・独自位置情報を同時に渡す。Alphaと透明画素内RGB、解像度情報を保持する。

OLE用の画像書き出しは、画像・コマ・ファイル名・形式・保存設定・メタデータが同じなら一時ファイルを再利用する。ファイルの削除・サイズ・更新日時の変化でも再作成する。編集ソフトがドロップ後に読むファイルは削除しない。画像データを重複してキャッシュしない。

高画質縮小は4,194,304画素以上の静止画・一時停止中のコマで非同期にする。必要になった時にだけCPUワーカーを1本作り、軽いLinearプレビューを先に、指定のLanczos3結果を後から送る。UIスレッドだけがDirect2Dを扱う。ズーム・画像変更・終了時には古い要求を行単位で取り消す。連続要求を無制限に積まない。大画像の連続リサイズ中も既存の表示タイルを使い、終了後に指定画質へ戻す。再生中のアニメーション、小画像、無補正・高速表示、編集の合成プレビューは従来の経路を使う。

APNGは符号化データの参照を索引し、既存libplumで1コマずつ復号する。合成後の全コマはシーク用に保持するが、全コマ分の合成前の復号バッファを重ねて持たない。SOURCE/OVER、BACKGROUND/PREVIOUS、除外された先頭画像、パレット、透明RGB、Adam7、1〜16bitを維持する。最適化対象外の構造には既存デコーダーを使う。破損データ・上限の検証は継続する。

PSDは既存PSD SDKに1チャンネル分の境界付きファイルビューを渡し、RAW/RLEを復号する。ZIPは既存minizで1チャンネルずつ展開する。出力RGBAへ変換したら一時チャンネルを再利用し、使用しない追加チャンネルも圧縮データを検証する。画像リソースは元ファイルから読む。SDK・ライブラリ本体は変更していない。

## 計測と確認

専用の非対話デスクトップ、独立したクリップボード、所有するテストプロセスを使用。非対話デスクトップはOSの更新領域を表示しないため、Appテストでは実際のInvalidateRect引数を記録して描く。別の永続DC上で、選択線と半透明・フチ・影付きペンの部分描画／全面描画の全画素を比較した。ComputerUse、ユーザーの画像・設定・クリップボードは使っていない。

APNG・PSDの合成試料384件と既存26件は、旧0.73.0のデコーダーと受理／拒否、画像サイズ、全フレームのSHA256、再生時間、ループ回数、画像保持量が一致した。色・Alphaの許容誤差を設けずに比較した。既存の独立した参照画像による合成テストも通過した。

| 合成試料 | ピーク私有コミット・旧 → 新 | 読み込み＋全コマハッシュ・旧 → 新 |
| --- | --- | --- |
| APNG 1024×1024・48コマ | 409.49 → 220.38 MB | 1679 → 1835 ms |
| PSD 3840×2160・16bit RAW | 167.56 → 117.69 MB | 287 → 303 ms |
| 同PSD・ZIP | 168.51 → 52.20 MB | 330 → 238 ms |

各版3回、順序を交互に変えた所有プロセスの中央値。MBは10進。APNGとRAW PSDは省メモリ化と引き換えに、この試料では読み込み時間が少し増えた。起動・画面提示・アプリ全体の倍率を表す計測ではない。

2048×1536のノイズRGBAをPNG・DIBV5・選択位置情報としてコピーする試料は、一時コミット増加が75.89 → 44.47 MB、コピー時間が471 → 391 ms（各版3回の中央値）。圧縮率の変更によってPNGのバイト数は変わるが、復号画素は一致する。コマ全体をコピーするアプリ経路では、さらに一時RGBA複製を省いている。

8M画素の高画質縮小のアプリ試験では、初回描画受付35ms、編集モードの切り替えを含め最終品質まで270ms。待ち時間の固定しきい値を合否にせず、計算中のコマンド受付、古い結果の破棄、同期版との最終画素一致で判定した。ファイル読み込み時間を含まない一例である。

UI配置の所要時間は実行時の変動が大きく、高速化率は断定しない。最終版の表示32件・基盤15件・転送6件、関連アプリ12件、専用自動操縦4本256操作・22画面、配布EXE主要10経路が通過した。

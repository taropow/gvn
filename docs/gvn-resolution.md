# 解像度と実寸によるサイズ指定

0.39.0へ配布反映済み。[今回の配布確認](verification/0.39.0-daily-use.json)を参照。以下には開発時点と旧版の記録も含む。

0.39.0へ配布反映済み。[今回の確認記録](verification/0.39.0-resolution-related.json)を参照。DPIの保存・コピー・ドラッグへの反映も[保存の関連確認](verification/0.39.0-resolution-save-related.json)が成功した。全体の完了とは扱わない。

「画像 → リサイズ」にプリント幅・高さと水平/垂直の解像度を追加した。長さはinch・cm・mm、解像度はdpi・dpcmを選択する。1 inch＝2.54 cm＝25.4 mmとして計算し、単位の切り替えだけでは画素寸法を変更しない。X/YのDPIは独立して保持する。ファイルで解像度が未指定なら72 DPIを使う。

「画像を拡大縮小」がONなら、プリント寸法とDPIから画素数を四捨五入して求める。比率固定がONなら元の画素の縦横比を保つ。DPI欄だけを変更した場合は画素数を保持し、表示するプリント寸法を更新する。従来の幅・高さ・倍率・半分・2倍・11補間方式・縮小後シャープも使える。

「画像を拡大縮小」がOFFなら解像度だけを変更する。元の幅・高さに固定し、画素寸法・倍率・補間などを無効にする。プリント寸法を変えた場合は、その軸の元画素数を実寸で割ってDPIを求める。画素データや共有キャッシュをコピー・変更せず、文書ごとの小さな情報として保持する。透明度、隠れたRGB、パレット、アニメの全コマ、表示中のコマと再生状態は保持する。静止画への変換確認も出さない。UndoはDPIと変更フラグを戻し、続けて画素を加工した場合も変更後のDPIを引き継ぐ。

「画像 → キャンバスサイズ」の単位はpx・%・inch・cm・mm。実寸指定はその文書のX/Y DPIから画素数に換算する。%は元画像に対する比率で、比率固定は実寸の比ではなく元の画素の比率を保つ。キャンバス自体の操作ではDPIを変更しない。9基準点・背景RGBAなどは従来どおり適用する。

解像度は各軸0.001～65,535 DPI、寸法は正の数を受け付ける。画素を作り直す操作では各辺・画素バッファ・設定したメモリ制限も検査する。解像度だけの変更では画素用のメモリ検査を通さない。不正な値ではOKを無効にし、確定できない。単位と拡大縮小ON/OFFの設定は成功した確定時だけ保存する。

関連単体/UI19件、本体4件、実コントロールの専用69・71・73で217操作・6画面を確認した。DPIのみの変更で元Imageと画素バッファのポインタが変わらず、元メタデータも変更されないこと、Undo、次の加工、GIFの再生、コピー、取消、不正値、成功時の設定保存を確認した。UIでは5単位・独立DPI・比率・小数換算を確認し、画面の文字と配置も目視した。

最初の追加テスト1件は、600÷(5.08÷2.54)の浮動小数点結果を300と完全一致で比較して失敗した。新規の換算期待値2か所を1e-8 DPI以内の比較に直し、製品コードは変えずにテストEXEだけを再ビルドした。失敗した記録も保持する。既存195件の本体ケース本文は維持した。テスト境界は、解像度だけの操作で画素メモリ検査を行わないように合わせた。

全体196件・CTest全体・専用73本全体・性能測定は繰り返していない。印刷レイアウト、画像情報の色数などは別工程として残る。ICCは有無の表示で、色変換やプロファイルの書き出しはまだ行わない。

参照は保存済みの[MassiGra拡大縮小](http://www.massigra.net/massigrahelp/currentver/d_resize.htm)と[画像サイズ](http://www.massigra.net/massigrahelp/currentver/d_imgsize.htm)。これまでの[リサイズ](gvn-resize.md)・[キャンバス](gvn-canvas.md)の画素処理と合わせて使う。

## DPIの保存と画像の受け渡し

PNGはpHYs、BMPはヘッダーのX/Y pixels/mへ最も近い整数を書き込む。最小は1 pixels/mで、DPIの刻みは0.0254となる。JPEGは整数のJFIF密度に加え、X/Y解像度とinch単位のEXIFを記録し、小数も保持する。既に画素の向きを補正しているため、元のEXIF方向は転記しない。GIFに絶対的なDPIの保存は行わない。

クリップボードPNGとドラッグ用PNG、外部アプリへ送る生成PNGにも文書のDPIを渡す。WindowsのPNGエンコーダーが密度を切り捨てる差を確認したため、DPIを指定したPNGの受け渡しには既存のlibpng保存を使う。RGBAは全値を保持する。DPIが未指定の場合は従来の受け渡しを維持する。画像を保存先へ結び直す設定とUndoも検査した。保存画面は専用74でPNG/BMP/JPEGを実際に確定し、作成したファイルを開き直してパスとDPIを照合した。

保存関連23件、本体2件、Pillowによる独立読取7ファイル、専用74の47操作・1画面を確認した。PillowのBMPのDPI表示はpixels/m÷39.3701という近似式なので、ファイル内の正確な整数密度とその表示値を分けて照合する。クリスタ等の実受信側でのDPI解釈は今回の確認範囲には含めない。

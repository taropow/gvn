# 明るさ・コントラスト・ガンマ調整

0.57.0。「画像 → 明るさ…」で3項目を同時に調整する。[確認記録](verification/0.57.0-brightness-related.json)。

| 項目 | 範囲 | 初期値 | バー |
| --- | --- | --- | --- |
| 明るさ | -255～255 | 0 | -255～255 |
| コントラスト | -255～255 | 0 | -255～255 |
| ガンマ | 0.400～2.500、小数3桁まで | 1.000 | -150～150 |

各行に数値欄、バー、初期値へ戻すボタンを置く。ガンマのバーは負側が1刻み0.004、正側が1刻み0.010。参照版で端点・中間点と数値からバーへの丸めを観測した。不正/範囲外の入力では説明を表示してOKを無効にする。参照版がガンマ範囲外を自動補正する点とは異なる。単独のコントラスト/ガンマコマンドも従来の操作として維持する。

プレビューはメイン画像へ表示する。操作から30ms待って更新し、短時間の連続入力をまとめる。プレビューOFFではOKまで計算しない。OFF・取消・処理失敗・対象画像の変更時はプレビューを取り下げる。値が変わらないOKでは計算済み画像を再利用する。画像全体の無変更値は画像確保もUndo追加もしない。数値は画面を開くたび0/0/1.000へ戻る。プレビューのON/OFFだけをOK時にINIへ保存し、取消では保存しない。旧設定はON。

明るさ、コントラスト、ガンマの順にRGBへ変換表を適用し、Alphaは変えない。全体処理で有効なインデックス画像ならパレットを編集し、番号、未使用色、重複色を保持する。選択範囲だけなら範囲外を変えず、元のパレット番号を再利用しない。表示画像は確定まで変更せず、確定全体を1回でUndoできる。元ファイルを自動上書きしない。アニメは既存の編集確認を通して現在のコマを対象にし、取消や失敗時は再生位置/状態を戻す。設定保存に失敗した場合も画像を置き換えない。

公式0.45の実コントロールで既定値、リセット、範囲、バー、プレビューの保持/取消を観測した。生成した256×3 RGB入力から18画像を取得。stage2は範囲外入力の想定が異なり途中失敗したが、その前に完了した13画像のコピー/Undoとハッシュを確認し、残り5画像を成功したstage3から取得した。stage2全体を成功とは扱わない。変換式は観測からの推定で、純明るさ/ガンマは差0、コントラストは最大1、組合せは最大2。任意画像・全パラメータの完全一致は主張しない。

基盤/実UI5件で参照画像、Alpha、選択、パレット番号、確保失敗、入力、バー、リセット、プレビュー、確定時再利用、設定を確認。App3件でコマンド経路、コピー/保存、Undo、アニメ、設定失敗、途中画像切り替えを確認した。旧App227件の本文は不変。現在の台帳は229件（今回3件/日付付き履歴226件）で全件再実行ではない。通常本体2プロセスでも参照色、Alpha、Undo、設定を確認し正常終了した。

画面は同一プロセス内の実Win32コントロールを再帰WM_PRINTで記録して確認した。通常本体への別プロセスPrintWindowが黒画像になる診断失敗は別に残した。撮影用分岐の追加後も製品本体と基盤5件/App3件の本文が変わらないため、それらは再実行していない。ユーザーのデスクトップ/クリップボード/画像は操作していない。

F056を実装済みへ更新する。F055のヒストグラム/RGB別レベル/自動設定/プレビューと、実クリスタ/物理環境の確認は残る。全体GOALは未完了。

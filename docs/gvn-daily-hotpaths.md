# 普段使いの処理の軽量化（0.71.1）

対象は画像送り・ツール切り替え・クリップボード貼り付け。表示品質、デコードできる形式、Alpha、Undoの仕様は維持する。

## 画像送りとメニュー

従来は画像を読み込んだ時や多くのコマンドの終了時に、非表示のメニューバーも含めて全項目・サブメニュー・テーマ用メタデータを再生成していた。メニューの付け直しによるウィンドウの配置・描画処理も重なっていた。

通常の画像送りと編集操作では既存のHMENUを再利用し、有効・無効とチェック状態を更新する。ポップアップを表示する直前にも現在の選択・編集状態を反映する。設定の適用、履歴の変更、フローティング編集の項目追加・削除では従来どおり再構築する。設定したキー名・登録先・外部アプリ名・履歴の更新を省略しない。

## 貼り付け

標準的な32bit BGRA/BGRX DIBはヘッダー、サイズ、マスク、画素の範囲を検証した後、各チャンネルの汎用マスク演算と整数除算を省いてRGBAへ変換する。Alphaが明示された形式では0〜255をそのまま保持し、透明画素のRGBも変更しない。Alphaのない従来のDIBは従来どおり不透明とする。

上下の行順、クリスタで観測したRGBマスクの重複、通常のDIB、非標準ビットフィールド、パレット形式の判定は維持する。非標準のチャンネル配置は従来の汎用変換を使う。

PNGやDIBなどのクリップボード入力を、デコード前にもう一度vectorへ全コピーする処理を省いた。クリップボードを開いている間だけHGLOBALをロックし、同期デコーダへ読み取り専用spanを渡す。正常終了・例外のどちらでもロックを解除する。2048×1536の32bit DIBなら、この中間バッファ約12MiBを省ける。これは削除したバッファの容量であり、プロセス全体のメモリ実測値ではない。

## 計測と確認

同じRelease構成、同じ2048×1536 RGBA画像、同じ非対話のネイティブデスクトップと専用クリップボードで変更前後を測る。各値は5ブロックの中央値。デコード／貼り付けは各ブロック3回、メニュー更新は10回。


| 処理 | 変更前 | 変更後 | 短縮 |
| --- | ---: | ---: | ---: |
| 32bit DIB変換 | 104.719 ms | 24.688 ms | 76.4% |
| 32bit DIB貼り付け | 111.123 ms | 32.187 ms | 71.0% |
| メニュー更新（非表示） | 4.522 ms | 0.315 ms | 93.0% |
| メニュー更新（表示） | 12.466 ms | 0.383 ms | 96.9% |

貼り付け計測はクリップボード取得からImageの生成・解放までで、トースト、キャンバス描画、DWMの表示完了は含めない。メニュー更新は画像を採用した時に行う更新処理だけを測り、ファイル読み込みや画面表示全体の速度とは区別する。

専用テストで全256段階のAlphaと透明RGB、上下の行順、クリスタ形式、非標準マスク、破損入力のフォールバックとロック解放を確認する。メニューは画像送り・選択・加工・Undo/Redo・フローティング編集・設定変更後に、都度新規生成したメニューの状態と突き合わせる。関連する既存テストとネイティブ自動操縦も実施する。

確認結果: 関連アプリ12件（計測を含む）、転送6件、隔離クリップボード1本、専用自動操縦2本135操作・10画面、配布EXE主要10経路が通過。

[検証記録](verification/0.71.1-daily-hotpaths-related.json)。普段使い用は `G:\gvn\app\gvd.exe`。既存ウィンドウを保持して更新し、次の起動から適用される。

最終0.71.1ではWindows標準メニューの状態を独自コマンドで書き換えないようにし、関連アプリ3件と専用画面1本76操作・6画面を再確認した。速度計測と転送の処理は変更していないため、直前候補の成功結果を継承した。配布EXE主要10経路も最終版で通過した。

# フォント選択と描画（0.44）

0.44へ配布反映済み。旧ラスターフォントと「@」付き字体、文字セット選択を追加した。[変更箇所の確認記録](verification/0.44.0-fonts-related.json)を参照。

Windows標準フォントダイアログで字体・スタイル・サイズ・下線・取消線・文字色・文字セットを選ぶ。サイズは内部で0.1pt単位とし、独自の1000pt制限を廃止する。標準ダイアログが返した正の値を保持する。元の0.45を隔離起動し、1/1639/32767/32768ptを再表示して保持値まで確認した。この4点は上限値の確定や全整数の総当たり試験を意味しない。

通常のTrueType/OpenType字体は従来のDirectWriteで描く。ラスターフォントおよび「@」付き字体は、GDIで字体・文字セット・ウェイト・斜体・装飾を指定し、白文字の被覆率を表示用マスクへ変換してDirect2Dで色・影・背景を合成する。選択されたフォントだけを調べ、起動時や設定画面表示時に全フォントを列挙しない。マスクは画像表示領域に収まる範囲だけを保持し、同じ文字・設定・領域の再描画で再利用する。通常字体へ戻すとマスクを解放する。

「@」字体ではWindows GDIの縦向き字形・約物を保つ。横書きキャプション全体を90度回して縦の列を組む機能は追加しない。これは[Windowsの@字体の説明](https://devblogs.microsoft.com/oldnewthing/20120719-00/?p=7093/)に対応するGDIの挙動である。[標準ダイアログの制限フラグ](https://learn.microsoft.com/en-us/windows/win32/dlgbox/font-dialog-box)も参照。

フォント・文字セット・0.1ptのサイズをINIへ保存し、適用・キャンセル・全画面ページの初期化に含める。古いINIに文字セットがなければDEFAULT_CHARSETを使う。DPI変換の途中の整数乗算によるオーバーフローも避ける。表示用の文字は元のRGBA、クリップボード、保存画像、OLE用PNGには焼き込まない。

確認は変更範囲に限定した。独立したGDI描画とSystem/＠MS Gothicの画素（日本語・装飾を含む）を照合し、既存の3背景×9位置と通常字体のキャッシュ、本体の表示条件/コピーを確認した。設定画面の69操作では、両字体と1639pt、文字セット選択の利用可否、保存・取消・初期化と透過コピーが成功した。32768ptは実描画でも範囲内へクリップし、INIでは大きな値を保持できると確認した。物理プリンタとの字形比較や、あらゆるインストール字体の画素検査を行った意味ではない。

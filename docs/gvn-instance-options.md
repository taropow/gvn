# 多重起動とアクティブ化設定

0.21.0で実装・検証し配布した。全体GOALは未完了。

一般タブのS001〜S003を対象にする。参照の説明と所有したMassiGraプロセスから採取した[既定値](verification/0.21.0-general-reference.json)を使う。参照では多重起動OFF、再利用時・ドロップ時のアクティブ化ON。GVNは多数起動するユーザーの使い方と既存動作を保ち、多重起動ONを既定とする。アクティブ化の2項目はONを既定とする。

## 動作の契約

- 多重起動ONなら、画像指定の有無にかかわらず独立した画面を作る。
- OFFなら、同じ設定ファイルを使う既存の画面へファイル指定を渡し、新しい画面は作らない。ファイル指定なしの場合も再利用する。設定ファイルが異なる場合は独立する。
- 設定ファイルの識別は絶対パスの字句正規化とWindowsの大文字化による。シンボリックリンクや短い別名を同じプロファイルへ統合する機能は対象に含めていない。
- 「多重起動しない場合にウィンドウをアクティブにする」は、多重起動OFFの時だけ設定操作できる。OFFでも受信して画像を開く。最小化中や非アクティブな最大化中に画像サイズ連動の表示方法が復元を引き起こさないよう、表示方法の再適用を後のアクティブ化まで保留する。
- ファイルのドロップ時のアクティブ化は別設定。Shellのファイルドロップで先頭のパスを受け付け、透明画像のRGBAは通常の読み込みと同じ経路で保持する。入力側のOLE IDropTargetと外部ソフトでの操作確認を完了したという意味ではない。
- モーダル設定画面を開いている時の起動要求は受信して保持する。本体が再び操作可能になってから開く。連続要求は最後のファイルを採用し、ファイル指定なしの要求で保留ファイルを消さない。
- 保存確認を有効にしている場合は、通常の画像切り替えと同じ確認を通す。

## 実装と検査

`InstanceStartup`は起動時だけ使う名前付きミューテックスで同時起動を直列化し、所有画面の登録とWM_COPYDATAで転送する。常駐の監視スレッドは追加しない。設定ファイルのハッシュだけでなく、ペイロード内の完全な識別文字列も照合する。送信側で画像パスを絶対化し、受信側のカレントディレクトリに依存させない。

相手の作成待ちは最大2秒、メッセージの応答待ちは750ミリ秒。相手が生存しているのに応答しない場合や受信を拒否した場合は、重複画面を作らずエラーにする。要求の受信確認中に画像の読み込みや保存確認ダイアログを実行しない。受信後のメッセージで処理する。

追加の全体回帰で、モーダル終了直後に自動操縦の待機が先に完了するケースを[保存](verification/0.21.0-before-modal-wakeup-fix/scope.json)した。本体はWM_ENABLEで保留処理を再通知し、自動操縦は読み込みだけでなく受信キューも待つ。178操作と期待値は変更しない。

最大化中のOFFも[実プロセスで再現](verification/0.21.0-before-maximized-fix/scope.json)した。前景判定には[GetForegroundWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow)を使う。[GetActiveWindow](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getactivewindow)は呼び出しスレッドのメッセージキューのアクティブ画面を返すため、別プロセスが手前にあるかの判定には使えない。同じ追加3ケースで修正を確認し、追加修正を含む全体回帰・クリスタのRGBA照合・配布本体の9プロセスケースも成功した。

検査は`instance_tests.cpp`の形式検査と所有HWND、`settings_tests.cpp`の全8組の保存、`app_tests.cpp`のキュー・モーダル・復元・画素、`37-general-instance.gvn`の実設定コントロール、`probe_gvn_instances.py`の実複数プロセスに分ける。専用の非対話ウィンドウステーションと設定を使い、ユーザーのウィンドウ・設定・クリップボードは操作しない。起動速度の比較は実行しない。

0.20.0では多重起動OFFでも別画面が作られることを[修正前の同一検査](verification/0.21.0-before-instance-fix/result.json)で再現した。関連5項目・本体79/設定28/形式5/実プロセス9ケースと専用37の178操作・4画面が成功した。[関連範囲とソース](verification/0.21.0-instance-related.json)を保存する。NUL入り入力は[変換前の検査](verification/0.21.0-before-instance-validation-fix/scope.json)で補強し、実プロセスで見つかった[最小化解除](verification/0.21.0-before-instance-restore-fix/scope.json)も同じ受信手順で修正を確認した。応答不能試験のエラー画面は、実ボタンが生成されてから押して終了させる。S001〜S003を実装済みへ進め、一般ページ全体の初期化は残項目があるため部分対応のまま。全31項目・79統合ケース・専用37本6,348操作・147画面と配布本体10経路が成功。[最終範囲](verification/0.21.0-instance-stage.json)を保存し、全体GOALを継続する。

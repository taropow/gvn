# ごみ箱を使わない直接削除

0.36.0へ配布反映済み。[配布の確認範囲](verification/0.36.0-daily-use.json)を参照。

「設定 → キー」または「設定 → マウス割当」の「ファイルを直接削除（ごみ箱を使わない）」を使う。新規設定ではShift+Deleteに割り当てる。既存の設定ファイルへ新しい破壊的なショートカットを自動追加しないため、更新した環境では明示的に登録する。キー設定の初期化を選んだ場合は新しい既定値を適用する。

この操作は、ごみ箱の設定にかかわらず実ファイルを直接削除する。通常のDeleteと「ごみ箱へ」の設定を変更しない。「削除前に確認する」がONなら完全削除の確認を表示し、取消では画像とファイルを保持する。削除失敗でも表示中の画像と元の場所を保持する。

「削除後に次の画像を表示」がONなら次の画像へ進む。OFFなら表示中の画像を保持し、Alphaを維持してコピーできる。削除済みの場所には文書を結び付けない。貼り付け画像・ZIP内画像・画像なしでは直接削除しない。

## 今回の確認

[関連検証](verification/0.36.0-direct-delete-related.json)では、設定55件、本体の削除関連3件、専用自動操縦3本284操作8画面を確認した。キーとマウスからの実行、確認の取消、保存と再読込、既存キーの維持、失敗時の保持、削除後の画像保持・次画像への移動を含む。削除対象は専用の生成ファイルに限定した。通常削除の本体統合試験ではごみ箱指定の受け渡しを確認し、実際のユーザーのごみ箱へは試料を送らない。

初回の新規テストは、テスト側で有効にしている未保存確認への応答が不足して失敗した。応答を追加し、製品コードを変更せずそのケースと未実行の自動操縦だけを確認した。初回の記録を残し、成功済みの設定55件と既存の削除2件は繰り返していない。

190件ある本体ケース全体、CTest全体、全67本の自動操縦を今回すべて実行したという意味ではない。追加の性能測定も行っていない。変更箇所と影響する日常操作を優先する。

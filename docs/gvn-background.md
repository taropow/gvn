# 背景タイルと透明部分の市松の補完

2026年10月20日。0.30.0で背景全体の6項目を照合した。[最終検証範囲](verification/0.30.0-background-stage.json)と[判定記録](verification/0.30.0-background-audit-review.json)を保存し、全体回帰と通常/軽量配布の検査が成功した。その他の未実装・実環境・性能・実編集ソフト受信は全体GOALで継続する。

## 確定した参照仕様

[公式の背景設定](http://www.massigra.net/massigrahelp/currentver/d_prop_bg.htm)と、[公式0.45を使った20条件・42画像の記録](verification/background-reference-0.45.json)を対応付ける。生成した7×11の不透明PNGを620×387の表示領域へ原寸中央表示し、2配色×5サイズ×タイルON/OFFを確認した。設定直後と再読込後、初期化、プレビューの計9,864,790画素が、独立した矩形の描画と元画像の貼り付けによるモデルに完全一致した。

| 項目 | 参照で確定した値・動作 |
| --- | --- |
| 背景をタイル状にする | 既定ON。画像外を含む表示領域全体へ適用 |
| 背景色1 | 既定RGB(32,32,32)。タイルOFFではこの色だけで塗り潰す |
| 背景色2 | 既定RGB(48,48,48)。タイルONのもう一方の色 |
| サイズの5択 | 最小8、小16、中32、大64、最大128px。既定は中 |
| 原点 | 表示領域の左上(0,0)が色1。セルごとに縦横へ交互に配置 |
| タイルOFF時 | サイズと色2の操作を無効にする。選択値は保持 |
| 初期化 | タイルON、中、上記2色へ戻る |
| プレビュー | 初期化後の250×109領域も、同じ32pxの2色モデルに全RGBが一致 |

カスタム色はRGB(23,45,67)/(89,101,113)を使用した。画像77画素と中央位置は全条件で維持され、背景の変更で元画像を変えていない。今回の正常系は96DPIの専用デスクトップ内であり、物理画面への提示速度や異なるDPIの互換性までは証明しない。

## 測定方法と限界

プローブが起動した公式0.45の子プロセス、専用ウィンドウステーション、生成画像、専用クリップボードだけを使用した。既存アプリやユーザーの画面・設定・クリップボードは使わず、起動速度比較も行わない。

別プロセスのPrintWindowは黒一色となり、同じプロセス内のWM_PRINTでもツールバー等だけが描かれて画像領域が未描画だった。この診断画像は成功証拠から除外した。実際の画像表示子ウィンドウ`TF811202_MassiGra_MaCl`とプレビューに対し、そのプロセス内で作ったメモリDCをBeginPaint/GetDCの対象として渡し、実際の描画処理を実行した。EndPaintでGDIを同期して画素を保存する。描画先の差し替えであり、物理画面を取得したという主張には使わない。

[GDIオブジェクトのハンドルはプロセスに属する](https://learn.microsoft.com/en-us/windows/desktop/SysInfo/gdi-objects)ことと、[WM_PRINTCLIENTはアプリ側の処理が必要](https://learn.microsoft.com/en-us/windows/desktop/gdi/wm-printclient)である点も確認した。観測器は対象PID・親PID・実行ファイルパスを照合し、Captureは非表示のウィンドウステーション内で同じプロセスに属するHWNDにだけ許可する。コード・参照EXE・観測器と取得画像のハッシュ、初回の失敗や未描画画像も記録した。

## 0.29.0配布本体で確認した不足

0.29.0の`Renderer::scene`は画像の矩形内だけへ透明部分の市松を描き、外側は別の単色である。未読込時は固定の暗い市松を描く。背景タブの2色・サイズ・プレビューは透明部分用の設定で、参照のウィンドウ背景全体の設定と同じ適用範囲ではない。

S012/S014/S015/S017に加え、実装済みと記録していたS013/S016も部分対応へ戻す。現行の2〜64pxでは参照の最大128pxを選べず、透明部分用のプレビューだけではウィンドウ背景のプレビューを再現していないためである。配布済み0.29.0の記録を上書きせず、開発中の台帳とここへ差分を示す。

0.29.0では、背景色や透明部分の色・サイズの変更時に`App::apply_settings`が`Renderer::reset_background`で描画先と画像用GPU資源まで作り直していた。開発本体ではパターンの更新を`reset_patterns`へ分け、描画先・画像のCPU/GPU資源を保持する。

## 開発本体で実装・確認した範囲

背景ページにタイルON/OFF、サイズ5択、色1・色2を追加した。サイズと色2の入力・色選択ボタンはタイルOFF時に無効にし、設定値は保持する。透明部分用の従来5項目も独立して残す。プレビューは背景全体の選択を表示し、9行の下へ配置してスクロール範囲にも含めた。プレビュー描画では2本のGDIブラシを使い回し、セルごとの生成・解放を避ける。

| Viewerセクションの追加キー | 既定値 | 範囲・意味 |
| --- | --- | --- |
| `background_tiled` | 1 | 0:色1の単色、1:2色のタイル |
| `background_pattern` | 2 | 0〜4が8/16/32/64/128pxに対応 |
| `background_first` | 2105376 (`202020`) | 0〜16777215、RGB色1 |
| `background_second` | 3158064 (`303030`) | 0〜16777215、RGB色2 |

旧`background`とAlpha用の4キーは保持する。新しい色1キーが欠落または空で、旧`background`が存在する場合だけ旧色を色1へ引き継ぐ。新色1の明示値を優先する。読み込みだけではINIを作成・変更しない。背景色メニューは新色1を選び、旧来の透明部分の単色も従来どおり更新する。

通常620×387の表示領域で、2配色×5サイズ×ON/OFFの20条件を実際の参照BMPと全RGB比較した。最初の4件の失敗を保存し、追加テストを保ったまま描画処理を修正した。原寸の奇数幅画像を中央へ置くと半画素位置になる差も検出し、1:1の画像と表示タイルの描画先を画素境界へ合わせた。透明部分の市松・単色と外側の背景は独立して検査した。パターン変更後の描画先生成時間は0で、画像変換バッファとサンプリングタイルも保持した。起動速度やフレーム速度の比較ではない。

実設定コントロール9項目で20条件のプレビュー全画素、無効化、適用、保存・再読込、取消、初期化、OK、他タブの未適用値保持を確認した。保存失敗は適用コールバックで注入し、ファイルと未適用値が保たれた。UI検査の識別子・型のビルドエラーも記録し、修正してから不足項目の負の検査を成立させた。

関連5項目は設定42件・描画19件・通常本体のUI起動・設定画面・アプリ統合143件が成功した。統合の追加30条件では静止PNG・GIF・APNGに各10通りの背景を適用し、画像の同一性、適用前後の読み込み世代、手動倍率・パン、再生コマと経過時間、全コマRGBA、コピー、PNG保存、ステータスアイコンからのOLEファイルデータを検査した。ファイル選択とOLEのモーダルループは既存のテスト境界で代替し、実クリスタでの受信を証明したものではない。

専用自動操縦は5本・779操作・38画面が成功し、新しい52番は443操作・5画面だった。未読込時は表示領域の全画素、画像表示時は画像と実際のキャプション矩形を除く背景を`WM_PRINTCLIENT`で比較する。比較画素が0なら失敗にする。全画面キャプションを背景の誤差とした初回の失敗と、保存操作の世代更新を背景適用の変化と混同した初回の統合失敗も保存した。両者は検査側で修正し、その間の本体71ファイルは変更していない。既存AppAuditの内容は新規メンバーと登録を除去すればバイト単位で同一だった。

上記の最初の関連検査は専用デスクトップ内の生成素材・メモリDCによる検査であり、物理画面・実DPI・性能・実編集ソフトの受信を検証したという意味ではない。この最初の関連検査の後に、後述の全体回帰と配布検証を実施した。

## 実装した契約

ウィンドウ背景用にタイルON/OFF、色1・色2、5段階のサイズを設け、背景ページの初期化・適用・OK・取消・INIへ接続する。既存の`background`色と、透明部分用の`checker`/`checker_light`/`checker_dark`/`checker_size`の明示値を保持する。透明部分用の市松は独立した追加機能として残し、背景全体の機能の代わりに数えない。

新規の既定は暗い32pxの市松とし、起動直後はこれだけを表示する。画像未読込の説明文等は描かない。背景を単色や別の色・サイズへ明示変更した場合は、その選択が分かるように反映する。透明部分の市松だけを切り替えても、背景全体の選択は変えない。コピー・保存・OLEのRGBAへ背景模様を焼き込まない。

画像外と未読込の背景は表示領域の原点に固定する。画像の移動・拡大でタイルを画像へ追随させない。描画先ごとの小さなパターンを再利用し、ウィンドウ全体の背景画像を毎フレーム確保しない。背景色やサイズの変更だけで、画像のCPU/GPUキャッシュや再生位置を捨てない。

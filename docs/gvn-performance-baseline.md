# 大画像・アニメ・多数起動の性能基準

0.34.0の改善前として、配布済み0.33.0を変更せずに測定した。新規追加は試料生成と計測のPythonツール2本。実行時のsrc/includeと配布ファイルは保持した。

## 測定範囲

合成6試料、各条件3回、42組126プロセス。4K JPEG/透過PNGは1/4/8個、8K透過PNGと4K16bit PSDは1/4個、1024×1024・48コマのGIF/APNGは1/2個。事前確認の13プロセスは集計へ混ぜない。画像ごとに独立したフォルダを使い、隣接画像の先読みを避けた。すべて専用の非表示ウィンドウステーション上で起動・正常終了した。

内部の採用完了と最初のDirect2D描画復帰までを記録した。プロセス生成・OleInitialize・DWM提示を含む総起動時間ではない。profileの固定1080×760・既定Linear・Software描画であり、通常起動480×360や物理画面の滑らかさを証明しない。OSファイルキャッシュは消去していない。実写真全般へ一般化しない。MassiGraの追加起動比較は行わない。

コミットピークは各プロセスが生存中に観測したOSの高水位値。保持量は描画後2秒のプライベートメモリ。集団の最大値は5ms間隔の同時観測で、個別ピークの合計とは分けた。[Windows APIの定義](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex)に従う。

## 改善の要件

2026-10-20のユーザー指示により、未着手の追加最適化と測定拡張は後回しにする。以下は改善候補と過去の測定記録として保持し、普段の操作と配布反映を優先する。APNGの240MiB目標やPSD調査を今回の配布の必須条件にしない。

- [x] 6試料の固定、専用計測器、事前13プロセス、3回42組126プロセスの基準測定。
- [x] GIFの全コマ二重保持を削減し、単独48コマのピーク240MiB以下を確認。[実装と検証](gvn-animation-memory.md)。
- [ ] APNGの全コマ二重保持も減らし、同じ単独48コマでピーク240MiB以下を確認する。
- [ ] 16bit PSDのSDK内の同時確保と読み出し経路を調査し、不要なコピーを減らす。
- [ ] 全RGBA、透明画素内RGB、GIFの表示方式/破棄/反復、APNGの合成/破棄/遅延/既定画像、シーク/一時停止/コマ送り/コピー/保存/OLE/Undoを保持する。
- [ ] 同じ試料で旧版/改善版を交互に測り、全サンプル・ピーク・保持量を比較する。既存の入力/デコード上限・非同期取消も維持する。
- [ ] 実写真・巨大アニメ・通常プロセス・実DPI/物理表示・多数起動の残条件を追加する。

この基準測定自体は改善前の記録。続くGIFの削減は上記の別記録で検証した。配布版は0.33.0、APNG等と全体GOALは継続する。

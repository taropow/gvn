# 実クリスタ受信の計画と結果

2026年10月21日にユーザーの操作許可を受け、配布0.58.0の軽量EXEと、ユーザーが起動したクリスタ5.0.1をそのまま使用して実行した。テスト文書のレイヤーを往復した全RGBAが一致した。[実行証跡](verification/0.59.0-csp-receive-related.json)。製品EXEの変更・再配布はしていない。

生成した64×48のPNGはAlpha0/1/63/127/128/254/255を持つ。通常GVNからコピーし、生成した透明PNGを開いたクリスタのテスト文書だけへ貼り付け、コピーしたレイヤーをGVNへ戻してRGBAを照合する。既存の制作ファイルは保存・終了しない。対象PID/実行ファイル、GVN、補助ツール、操作対象と生成ファイルのハッシュを計画へ固定する。

実行では一時的に前面ウィンドウ/カーソルが変わり、共有クリップボードをテスト画像で上書きした。検証文書は確認用に開いたまま残した。[実行ゲート](../tools/clipstudio_interop.py)は計画ハッシュと明示的なデスクトップ操作・クリップボード上書き・既定ショートカット確認を必要とする。準備時の不変なplan.jsonのexecution_authorized=falseは計画だけでは実行許可を与えない意味であり、実際のユーザー回答と実行記録は別の証跡に保存している。

ファイル選択画面は実際のEditが初期化されてフォーカスを得てから通常キー入力を送り、パス全体の入力完了を待つ。途中停止時には、この試験が開いたダイアログだけを取り消す。共有クリップボードへ触る前とクリスタの編集前には、生成ファイル名による文書の識別を行う。無関係なタブを操作せず、OCRの画面切り出しは一時ファイルとして直ちに削除する。他の文書名やOCR文字列は記録しない。

この計画にOLEドラッグの実受信は含まない。Alpha貼り付けの成功をOLEの成功へ読み替えない。ComputerUse/Skyは使用していない。
